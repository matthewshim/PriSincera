# 게이트를 세운 주에, 눈이 더 많이 찾았습니다

게이트는 같은 실수가 돌아오는 것을 막습니다. 새로 생긴 실수를 찾아주지는 않습니다.

지난 한 주에 두 가지를 했습니다. 하나는 AI가 만들어 온 디자인 패턴을 여덟 계층으로 나눠 정리하고, 기계가 집행할 수 있는 것을 전부 게이트로 바꾼 일입니다. 다른 하나는 그 게이트를 전부 통과한 지면을 눈으로 다시 뒤진 일입니다.

후자가 더 많이 찾았습니다.

## 1. 기계로 접을 수 있는 것은 접었습니다

디자인 시스템 문서의 리비전은 스물다섯 번을 지나 있었습니다. 그런데 품질은 그만큼 올라가 있지 않았습니다. 리비전 대부분이 "지적이 들어왔다, 조항을 추가했다"의 반복이었고, 조항은 사람이 기억해야 집행되는 것이었습니다. 규범은 두꺼워졌는데 집행은 그대로였습니다.

그래서 조항을 늘리는 대신 세는 장치를 만들었습니다.

| 지표 | 전 | 후 |
| :--- | ---: | ---: |
| 집행되는 디자인 차원 | 1 / 12 | 12 / 12 |
| 타입 스케일 단계 | 35단 | 11단 |
| 브레이크포인트 | 10종 | 5종 |
| 죽은 CSS 규칙 | 194 | 0 |

`transition: all` 60여 곳과 `!important` 60여 건은 각각 0과 한 자릿수로 내렸고, 토큰 없이 박혀 있던 색값 300여 개도 대부분 걷었습니다. CSS는 1,600줄 넘게 줄었습니다.

핵심은 숫자가 아니라 **임계값이 아니라 래칫(ratchet)을 썼다**는 것입니다. 목표값으로 임계를 걸면 당장 빌드가 깨져서 아무도 쓰지 않습니다. 현재값으로 걸면 아무것도 개선되지 않습니다. 그래서 단조 감소만 허용했습니다. 기준선을 넘으면 빌드를 막고, 기준선보다 낮아지면 그 자리가 새 바닥이 됩니다. 더 나빠질 수는 없고, 좋아지면 거기서 잠깁니다.

같은 방식으로 어휘도 접었습니다. 버튼은 알약형과 사각형이 지면마다 섞여 있었는데 사각 하나로 통일했고, 라벨 선두에 박혀 있던 이모지는 자작 SVG 아이콘으로 바꿨습니다. 글리프는 OS마다 폭과 베이스라인이 달라서, 같은 코드가 환경에 따라 다르게 정렬됩니다. 눈으로는 "조금 어긋났다"로만 보이고 원인이 글꼴에 있다는 것을 알 방법이 없는 종류의 결함입니다.

만든 쪽이 가장 먼저 걸렸습니다. 경력 블록에 연도 축을 넣다가 같은 셀렉터를 두 번 선언했고, 그 자리에서 막혔습니다. CSS에서 중복 선언은 문법 오류가 아니라서 빌드도 통과하고 화면도 멀쩡해 보입니다. 나중에 둘 중 하나를 고치면 다른 하나가 조용히 덮습니다.

## 2. 제품이 늘수록 길어지는 구조를 끊었습니다

홈의 제품 섹션은 제품 하나를 추가할 때마다 404px씩 길어지는 구조였습니다. 제품이 다섯 개가 되자 섹션 높이가 2,216px이 됐습니다. 900px 뷰포트에서 **두 화면 반**입니다. 스크롤을 두 번 반 내려야 다음 섹션이 나온다는 뜻이고, 여섯 번째 제품을 만들면 더 길어집니다.

원인은 카드가 담은 정보 단위였습니다. 제품명, 서술 태그, 영문 라벨, 설명 두세 행, 태그 세네 개, CTA 버튼, 그리고 제품마다 전용으로 그린 CSS 아트. 일곱 단위였습니다. 특히 CSS 아트는 제품당 평균 180줄씩 900줄이 넘었는데, 이것이 **모든 게이트를 통과하고도 눈에는 결함**이던 자리입니다. 토큰을 썼고 중복도 없고 죽은 규칙도 아니었습니다. 그냥 제품마다 다른 그림이 들어가 있어서 다섯 개가 한 섹션으로 읽히지 않았습니다.

정보를 **세 단위로 고정**했습니다. 제품명, 한 줄 요약, 태그 두 개입니다. 카드 안의 CTA 버튼도 뺐습니다. 버튼을 두면 클릭 대상이 둘이 되어 "카드와 버튼 중 어디를 누르나"라는 질문이 생기므로, 카드 자체를 링크로 만들고 어포던스는 우측 하단 화살표가 맡게 했습니다.

| | 전 | 후 |
| :--- | ---: | ---: |
| 섹션 높이 | 2,216px | 756px |
| 제품 추가당 | 개당 +404px | 두 개당 +184px |
| 카드 정보 단위 | 7 | 3 |
| 섹션 CSS | 1,100여 줄 | 240여 줄 |

두 화면 반이 0.8화면이 됐습니다. 더 중요한 것은 증가율이 꺾인 것입니다. 제품이 늘어도 섹션은 선형으로 길어지지 않습니다.

제품 사이에 위계를 매기는 안은 쓰지 않았습니다. 대표 제품을 크게 놓고 나머지를 작게 두면 섹션은 더 짧아지지만, 그것은 디자인 결정이 아니라 사업 결정입니다. 모든 제품을 같은 크기로 두고, 줄이는 쪽은 카드가 담는 정보에서 찾았습니다.

## 3. 그런데 게이트가 통과시킨 것들

여기까지가 기계로 할 수 있는 일입니다. 문제는 이 전부를 통과한 지면이 여전히 어긋나 있었다는 것입니다.

앞서 리비전을 들췄을 때 한 가지가 더 보였습니다. **발견의 출처가 거의 전부 눈이었습니다.** 조항을 추가한 대응은 틀렸지만, 찾아낸 것은 언제나 사람이 본 것이었습니다. 게이트를 세웠다고 눈이 할 일이 줄어드는 것이 아니라 역할이 갈린 것입니다. 게이트는 이름을 붙인 패턴의 재유입을 막고, 눈은 아직 이름이 없는 결함을 찾습니다.

그래서 토큰은 통과하는데 눈에는 틀린 것만 보는 QA를 따로 돌렸습니다. 나온 것 중 넷을 적습니다.

**카드 아래 여백이 위와 네 배 차이였습니다.** 재 보니 96px인데, 그 값을 쓴 곳은 어디에도 없었습니다. 컨테이너의 아래 패딩과 다음 블록의 위 마진이 **더해진 값**이었습니다. 둘 다 "아래 여백"을 주고 있었는데 합을 아무도 보지 않았습니다. 토큰만 보면 양쪽 다 올바른 값입니다. 합은 토큰이 아닙니다.

**구분선이 오른쪽에서 끊겨 보였습니다.** 선을 그리는 규칙이 읽기 폭 제한과 테두리를 한 덩어리로 갖고 있어서, 선이 본문 읽기 폭을 물려받았습니다. 바로 위 블록은 컨테이너 폭을 꽉 쓰고 있었으니 오른쪽에서 270px 넘게 단차가 났습니다. 책임을 쪼갰습니다. 선과 패딩은 바깥 래퍼가, 읽기 폭은 안쪽 본문 요소가 갖습니다. 전역을 실측해 보니 컨테이너 폭을 쓰는 선이 스물두 건, 읽기 폭을 쓰는 선이 두 건이었습니다. 지배 패턴에서 이탈한 쪽이 결함이었습니다.

**연도 축의 좌우 여백이 네 배 가까이 벌어져 있었습니다.** 좌측 정렬된 연도가 칼럼 폭을 다 쓰지 않아 생긴 차이였습니다. 칼럼을 좁히고 간격을 줄여 맞췄습니다. 우측 정렬로 바꾸면 좌우는 같아지는데 섹션 좌단과 어긋나서 쓰지 않았습니다.

**다섯 항목 중 하나만 문구가 두 줄로 넘어갔습니다.** 글자 수를 세 보니 나머지 평균의 두 배가 넘었습니다. 줄였습니다.

넷 다 측정값은 규범 안에 있었습니다. 간격은 전부 토큰이었고 글자 크기도 11단 스케일 안이었습니다. 합이 틀렸고, 상속이 틀렸고, 비율이 틀렸고, 길이가 틀렸습니다. 어느 것도 셀 수 있는 형태가 아니었습니다.

한 가지 덧붙이면, 그 넷을 보면서 지적된 것 중 결함이 아닌 것도 있었습니다. 같은 블록의 "문구와 버튼 정렬이 어긋난 것 같다"는 지적은 확인해 보니 좌측 리딩 규정대로였습니다. 눈이 찾아낸 것도 재 보고 판정해야 합니다. 눈은 어디를 볼지 알려주고, 판정은 숫자가 합니다.

## 4. 화면의 숫자가 데이터가 아니었습니다

메인 히어로에는 열두 별자리가 떠 있고 각각에 좌표와 거리와 등급이 붙어 있습니다. 그 값이 어떻게 만들어지는지 들여다봤습니다.

```js
const raHours = Math.floor(ci * 2).toString().padStart(2, '0');
const distLy  = 350 + ci * 85;
const appMag  = (1.1 + ci * 0.15).toFixed(1);
```

`ci`는 배열 순번입니다. 적경은 2시간씩, 거리는 85광년씩, 등급은 0.15씩 가지런히 늘어섭니다. 분은 고정 문자열이었습니다. 게다가 별자리는 별 하나가 아니므로 거리와 등급을 별자리 단위로 쓰는 것 자체가 성립하지 않습니다.

아무도 신고하지 않을 결함입니다. 그럴듯해 보이고, 확인하려면 천문 자료를 찾아야 하고, 틀렸다고 해서 무엇도 깨지지 않습니다. 그래서 더 나빴습니다. "Sincerity, Prioritized."를 내건 지면이었습니다.

값을 데이터로 옮기고 대표 별 기준으로 다시 썼습니다.

```
RA 10h 40m / DEC +14° · α Regulus · Mag 1.35 · 79 ly
```

중심 좌표는 IAU 공표 경계, 거리는 시차 관측 기준으로 다시 조사했습니다. 오차가 큰 값에는 근삿값 표시를 붙였습니다. 그리고 순번으로 만든 값이 다시 들어오지 못하게 정합 게이트를 걸었습니다.

별 밝기도 눈대중으로 올리지 않았습니다. 배경 별 분포를 실측해 보니 별자리에 쓰던 값이 가장 밝은 배경 별에 묻히는 구간에 있었습니다. 분포를 기준으로, 패턴은 읽히되 배경과 경쟁하지 않는 지점에 맞췄습니다.

배치는 더 돌아갔습니다. 열두 별자리를 실제 황도를 따라 호로 배열하자는 안을 먼저 그려 봤는데, 진짜 호를 그리면 본문 카드와 히어로 로고를 관통합니다. 중앙을 비우는 제약을 지키면 결국 외곽을 도는 경로가 됩니다. 그러니 할 일은 "호로 바꾸기"가 아니라 **외곽을 한 방향으로 연속해서 돌게 만드는 것**이었습니다. 기존 구조는 위쪽 넷, 좌우 지그재그 넷, 아래쪽 넷이라 측면에서 순서가 끊겼습니다.

여기에 화면 폭별 단계를 더해 좁은 화면에서는 일부만 띄웠습니다. 별이 퍼지는 범위와 라벨 폭까지 포함해 경계 상자를 실측했더니, 교정 전에는 모바일에서 화면 밖으로 나가거나 서로 겹치는 별자리가 열 개 넘게 있었습니다. 지금은 본문 폭이 화면을 꽉 채우는 구간을 빼면 전부 0입니다.

## 5. 받은 분석을 집행 목록으로 쓰지 않았습니다

이 작업의 출발점은 외부에서 받은 메인 페이지 분석 문서였습니다. 쓸 만한 지적이 있었습니다. 그래서 바로 집행하지 않고 항목마다 코드에 대조했습니다.

대조에서 사실과 다른 항목이 열 건 나왔습니다. 두 가지만 적습니다. "30fps가 문제다"라는 지적이 있었는데, 그것은 의도된 상한이고 주석에도 적혀 있습니다. 히어로가 화면 밖이면 더 내립니다. 최적화를 결함으로 읽은 것입니다. "구조화 데이터가 없다"는 지적도 있었는데, 서버가 아티클 구조화 데이터를 주입하고 있었습니다. 홈에만 없는 것이 사실이었고, 그래서 그 항목은 범위를 좁혀 채택했습니다.

규범과 충돌해 반려한 것도 있었습니다. 그중 하나는 라벨과 본문의 글자 크기를 임의의 px로 지정하자는 제안이었습니다. 이것은 반려하되 번역했습니다. "12~13px로 올린다"가 아니라 "역할을 한 단 위 토큰으로 올린다"로 바꾸면 11단 스케일 안에서 같은 결과가 나옵니다. 외부 제안은 대개 이렇게 옮길 수 있고, 옮길 수 없으면 그것은 규범을 바꾸자는 말입니다. 그때는 제안을 집행하는 것이 아니라 규범을 다시 결정해야 합니다.

**가장 큰 발견은 대조가 아니라 구현 중에 나왔습니다.** 메타 태그가 두 곳에 있고 서로 달랐는데, 정적 미들웨어의 자동 index 제공이 루트 요청을 가로채고 있었습니다. 그래서 홈만 메타 파이프라인을 아예 타지 않고 정적 파일의 값을 쓰고 있었고, 다른 모든 경로는 파일이 없어서 서버 쪽으로 내려가 제대로 된 메타를 받고 있었습니다. 출처가 둘로 갈려 있었고, 갈린 쪽이 하필 홈이었습니다. 조치는 자동 index 제공을 끄는 한 줄이었습니다. 그 뒤로 모든 경로가 같은 파이프라인을 탑니다.

외부 시각이 쓸모없다는 얘기가 아닙니다. 이 작업의 절반은 그 문서가 가리킨 자리에서 시작했습니다. 다만 **가리킨 자리와 적힌 진단은 다른 것**이고, 둘을 구분하지 않으면 남의 추측을 우리 코드에 집행하게 됩니다.

## 6. 두 장치는 대체재가 아닙니다

게이트는 알려진 패턴의 재유입을 막습니다. 사람의 기억을 요구하지 않는 유일한 장치입니다. 그 대신 이름을 붙인 것만 막습니다.

눈은 이름이 없는 것을 찾습니다. 두 값의 합이 96px이 되는 것, 선이 엉뚱한 폭을 물려받는 것, 한 문장만 두 배 긴 것, 순번으로 만든 숫자가 브랜드 주장과 부딪히는 것. 전부 측정값이 규범 안에 있는 상태로 틀려 있었습니다.

그래서 순서가 있습니다. 눈이 찾고, 게이트가 잠급니다. 이번 주에 찾은 것들도 그 순서로 처리했습니다. 간격은 토큰으로, 선의 폭은 규범과 하드 규칙으로, 가짜 수치는 정합 게이트로, 발행물의 장식은 빌드 차단으로 각각 잠겼습니다. 다음에 같은 것이 들어오면 사람이 아니라 빌드가 막습니다.

품질은 조항으로 올라가지 않습니다. 눈으로 찾고 장치로 잠글 때 올라갑니다.
