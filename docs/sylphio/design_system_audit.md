## 2. 결함 상세

### A. i18n 사전이 지면 안에 있다 —

3지면이 파일 안에 `TRANSLATIONS` 객체를 들고 있고, **다른 모든 지면은 `src/locales/*.json`을 씁니다.**

| 지면 | 자체 사전 | 비교군 |
| :--- | :--- | :--- |
| `SylphioLanding.jsx` | 197줄 · 키 186개 | — |
| `SylphioApiKeyGuide.jsx` | 146줄 · 키 129개 | — |
| `SylphioPrivacy.jsx` | 113줄 · 키 27개 | — |
| **합계** | **456줄 · 342키** | `WaymarkLanding` 0 · `PlannersView` 0 |

**이것이 실제 사고를 냈습니다.** 자체 사전 때문에 세 파일이 `design-check`의 `I18N_EXCLUDE`에 올라 있었고, 그 사각지대에서 **결제 모달의 한국어 5건이 en·ja 사용자에게 그대로 노출**되고 있었습니다(2026-11-01 발각·수정). 당시 게이트를 `ko:` 블록 단위 마스킹으로 바꿔 제외를 해제했지만, **사전의 위치 자체는 그대로**입니다.

남는 비용:
- 로케일 추가 시 **4곳**(json 3개 + 지면 3개)을 고쳐야 합니다.
- 번역 누락이 빌드 타임에 드러나지 않습니다(`t()`는 키 폴백이 있지만 자체 사전은 `undefined`).
- 같은 문자열이 json과 지면에 중복될 수 있습니다.

**조치**: `home.service*` 패턴처럼 `sylphio.*` 네임스페이스로 `src/locales/*.json`에 이관하고 `t()` 경유로 바꿉니다. 342키라 기계적이지만 분량이 있습니다.

### B. 가이드 헤딩 레벨 건너뜀 4건 —

`SylphioApiKeyGuide.jsx`의 런타임 헤딩 순서:

```
h1 → h4 → h2 → h5 → h5 → h2 → h5 → h2 → h3 → h5 → h5
      ↑           ↑     ↑                 ↑
   h1→h4       h2→h5  h2→h5            h3→h5
```

| 위치 | 현재 | 내용 | 있어야 할 레벨 |
| :--- | :--- | :--- | :--- |
| L240 | `h4` | `byokTitle` (BYOK 설명 — 섹션급) | `h2` |
| L292 | `h5` | `geminiFreeTitle` | `h3` |
| L296 | `h5` | `geminiPayTitle` | `h3` |
| L316 | `h5` | `openaiWarningTitle` | `h3` |
| L410 | `h5` | `faq1Q` (FAQ 질문) | `h3` |
| L415 | `h5` | `faq2Q` | `h3` |

**원인은 분명합니다 — 구조가 아니라 크기로 헤딩을 골랐습니다.** `h4`·`h5`가 기본 글자 크기가 작아서 쓰인 것이고, 그 결과 스크린리더의 문서 개요가 끊깁니다(WCAG 1.3.1 Info and Relationships). 다른 두 지면은 위반이 없습니다(Landing `h1→h2→h3`, Privacy `h1→h2`).

**조치**: 레벨을 구조대로 되돌리고 **크기는 클래스로** 줍니다. `--fs-*` 토큰이 이미 11단이라 `h3`에 작은 크기를 주는 데 문제가 없습니다.

### C. 모바일 서브내비 = 스크롤바 숨긴 가로 스크롤 —

`SylphioNav.css` `@media (max-width: 640px)`:

```css
.sylphio-tabs-nav {
  overflow-x: auto;
  -webkit-overflow-scrolling: touch;
  scrollbar-width: none;          /* ← 신호 제거 (1) */
  -ms-overflow-style: none;       /* ← 신호 제거 (2) */
}
.sylphio-tabs-nav::-webkit-scrollbar { display: none; }  /* ← 신호 제거 (3) */
```

**홈 `Proof of Work`에서 결함으로 판정해 제거한 것과 정확히 같은 패턴**입니다(2026-11-02, 오너 "스와이프되는 기이현상" 제보 → §9-14에 "가로 캐러셀 금지" 명문화). 탭이 4개라 좁은 화면에서 넘칠 수 있는데, **넘친다는 표식이 0개**입니다 — 마지막 탭(고객지원)에 닿지 못할 수 있습니다.

**조치 후보**:
1. **탭을 줄바꿈**(`flex-wrap: wrap`) — 4개뿐이라 2행이면 들어갑니다. 가장 단순하고 신호 문제가 사라집니다.
2. 아이콘만 남기고 라벨을 숨긴다 — 4개가 한 줄에 들어갑니다. 다만 라벨 없는 탭은 의미가 약해집니다.
3. 가로 스크롤을 유지하되 **스크롤바를 되살리거나** 끝단 페이드·화살표를 둡니다.

**권고 ①** — §9-14가 이미 "짧은 목록에 캐러셀을 쓰지 않는다"는 판단을 세웠고, 4개는 짧은 목록입니다.

### D. 장식 목업이 실제 헤딩을 쓴다 —

`SylphioLanding.jsx`의 **결제 모달 목업**(실제 결제가 아닌 시연)이 실제 헤딩 요소를 씁니다:

| 위치 | 요소 | 내용 |
| :--- | :--- | :--- |
| L544 | `h3` | `{purchaseStatus}` (결제 진행 상태 — 상태 메시지) |
| L549 | `h2` | `"Sylphio Pro Lifetime"` (목업 모달 제목) |

문서 개요에 **가짜 섹션 2개**가 들어가고, 특히 `h2`는 실제 섹션 제목들과 같은 레벨입니다. 모달이 닫혀 있을 때는 렌더되지 않지만, 열리면 개요가 바뀝니다.

**조치**: 목업 내부는 `div`/`p` + 클래스로 바꿉니다. 모달에 접근명이 필요하면 `role="dialog"` + `aria-label`로 주는 것이 맞습니다(지금은 모달 시맨틱도 없습니다).

### E. 생hex 14건 — 8건은 토큰화 가능 —

선언부 **14건**입니다(주석 안의 2건 제외 — 전체 grep은 16건으로 나옵니다).

| 값 | 횟수 | 용도 | 판정 |
| :--- | :--- | :--- | :--- |
| `#ff5f56` · `#ffbd2e` · `#27c93f` | 각 1 (3) | macOS 창 트래픽 라이트 | **정당** — 플랫폼 모방이 목적 |
| `#3b82f6` ×2 · `#2563eb` ×1 | 3 | 결제 버튼 (App Store 블루) | **정당** — 동일 |
| `#ffb800` ×2 · `#ff8a00` ×2 | 4 | PRO 배지 금색 그라디언트 | **토큰화 가능** → `--color-gold` 계열 |
| `#1e3c72` ×1 | 1 | 히어로 그라디언트 시작색 | **토큰화 가능** |
| `#050505` ×2 · `#11131c` ×1 | 3 | 근-검정 표면 | **토큰화 가능** → `--bg-void`(#020205) · `--bg-surface`(#0E0E1A) |

정당 6건 · **토큰화 가능 8건**입니다.

형제 지면은 `WaymarkLanding` 0건 · `PlannersView` 0건 · `ReLearn` 2건입니다. **Sylphio만 14건**이고, 그중 과반이 모방 목적이 아닙니다.

`#050505`·`#11131c`는 선언 토큰과 **값이 다릅니다**(각각 #020205·#0E0E1A). 토큰과 나란히 쓰이면 미세한 색 불일치가 생깁니다 — 같은 "검정"이 지면마다 다른 셈입니다.

### F. `max-width: 820px`가 3지면에 —

| 파일 | 위치 |
| :--- | :--- |
| `SylphioLanding.css:54`, `:107` | 섹션 헤더 설명 |
| `SylphioApiKeyGuide.css:60` | 히어로 태그라인 |
| `SylphioPrivacy.css:60` | 히어로 태그라인 |

**§3-3 폭 체계에 없는 값**입니다. 정본은 `--measure`(860px)이고, 820은 세 파일이 공유하는 **비공식 사실상 표준**입니다. 40px 차이라 눈에는 안 띄지만, "토큰 밖의 값이 합의 없이 퍼진" 상태이고 §9-11이 "프로스는 `--measure`"를 규정합니다.

**조치**: `--measure`로 수렴하거나, 820이 필요한 이유가 있다면 **토큰을 신설하고 §3-3에 등재**합니다.

### G. 생px 간격 15건 —

`SylphioLanding.css` 기준. 성격이 둘로 갈립니다.

**토큰화 가능 (레이아웃)**
- `L23 padding: 160px 24px 64px` — 히어로. `--space-*`에 160px이 없어 토큰 신설 또는 `clamp()` 필요
- `L158 padding: 20px 24px` · `L568 padding: 30px` · `L617 padding: 10px` · `L653 padding: 20px 0`
- `L188 margin: 0 0 10px 0` · `L599 margin: 0 0 8px 0`(= `--space-sm`) · `L605 margin: 0 0 24px 0`(= `--space-lg`) · `L667 margin: 0 auto 16px`(= `--space-md`)

`8px`·`16px`·`24px`는 **토큰과 값이 정확히 같아 무손실 치환**이 됩니다(각 `--space-sm`·`--space-md`·`--space-lg`).

**일러스트 기하 (유지 권고)**
- `L485/501 padding: 2.5px 6px` · `L518 padding: 3px 6.5px` · `L540 padding: 1.5px 4px` — macOS 목업 내부 배지. 4pt 격자가 지배하지 않는 영역입니다(§4-5가 다루는 레이아웃 간격이 아님).

### H. rgba 생값 49건 —

| 파일 | rgba 생값 |
| :--- | :--- |
| `SylphioLanding.css` | **49** |
| `ReLearn.css` | 41 |
| `WaymarkLanding.css` | 22 |
| `PlannersView.css` | 11 |

알파 파생을 `color-mix(in srgb, var(--token) N%, transparent)`로 하지 않고 `rgba(...)` 생값으로 적은 건수입니다. 레포에 `color-mix` 전례가 있습니다(`WorkSection`·`AdminDashboard`). 다만 **ReLearn도 41건**이라 Sylphio 고유 문제는 아니고, 전역 백로그 성격입니다.

### I. 섹션 리듬 문법이 형제와 다르다 —

| 지면 | 리듬 방식 |
| :--- | :--- |
| `WaymarkLanding` | `.wm-section { margin-top: var(--space-2xl) }` — **섹션 간 여백** |
| `SylphioLanding` | `.sylphio-section { padding: var(--space-2xl) var(--space-lg) }` — **섹션 내부 패딩** |

둘 다 토큰을 쓰므로 게이트는 통과하지만, 결과가 다릅니다 — 패딩 방식은 **인접 섹션의 패딩이 더해져** 간격이 2배가 되고, 배경이 있는 섹션에서는 여백이 섹션 안에 갇힙니다. 형제 지면들과 세로 리듬이 어긋나는 원인입니다.

## 3. §9-11 문서형 레이아웃 — 준수 확인

가이드·개인정보는 §9-11이 **적용 사례로 명시**한 지면입니다. 조항별 실측:

| 조항 | Guide | Privacy | BuildersLogDetail(기준) | PlannersViewDetail(기준) |
| :--- | :--- | :--- | :--- | :--- |
| 사이드바 `position: sticky` | O | O | O | O |
| sticky top 오프셋 | 108px | 108px | 68px | 68px |
| 사이드바 폭 300px | O | O | O | O |
| 본문 `--measure` | O | O | O | O |
| 스크롤스파이 | O | O | O | O |
| `scroll-margin-top` | O | O | **X** | **X** |
| 하단 크로스내비 | X | X | O | O |

- **sticky 108px은 규범대로입니다** — §9-11이 "GNB, 있으면 서브내비 합산"을 규정하고 Sylphio는 서브내비가 있습니다.
- **`scroll-margin-top`은 Sylphio에만 있습니다.** 기준 지면 두 곳에 없는 것이 오히려 결함이고, 앵커 점프 시 헤딩이 고정 바에 가립니다 → **별건으로 기준 지면을 고칠 일**입니다.
- **하단 크로스내비 부재는 문제가 아닙니다.** §9-11 v5.20의 조건은 "사이드바가 **유일한** 교차 탐색 수단인 화면"인데, Sylphio는 서브내비가 모바일에서도 sticky로 살아남습니다. 단 **C가 해결되어야** 이 결론이 유지됩니다(지금은 탭에 닿지 못할 수 있음).
- 브레이크포인트는 640 / 768 / 1024로 **역할 3티어 정본을 지킵니다**.

**§9-1 히어로**는 3지면 모두 준수합니다 — 그라디언트 + `display: inline-block`(짧은 타이틀이 풀폭 그라디언트 중간만 샘플해 단색으로 렌더되는 사고를 막는 필수 선언).

## 5. 오탐으로 판정한 2건

측정 중 결함으로 보였으나 확인 결과 아닌 것을 남깁니다 — 같은 오판을 반복하지 않기 위해서입니다.

**오탐 1 — "Landing에 유휴 구동 애니메이션 5건"**

CSS 셀렉터만 보면 5건이 `:hover`·`.active` 같은 상태 게이트 없이 `animation`을 갖습니다:

```
.sylphio-cursor-pulse          cursorBlink 1s infinite alternate
.sylphio-mock-paywall-overlay  fadeIn 0.25s
.sylphio-mock-paywall-modal    scaleUp 0.3s
.success-checkmark             popSuccess 0.4s
.spinner                       spin 0.8s linear infinite
```

그러나 **전부 JSX 조건부 렌더로 게이트**됩니다 — `{isPlaying && <span className="sylphio-cursor-pulse">`, 결제 모달은 상태가 열렸을 때만 마운트, `.spinner`는 결제 진행 중에만. **게이트가 CSS가 아니라 JSX에 있는 경우**이고, 유휴 비용은 0입니다.

> 교훈: `glow-idle-visible`·`infinite-ungated` 지표는 CSS 셀렉터로 상태 게이트를 판정합니다. **JSX 조건부 렌더는 그 판정에 보이지 않습니다** — 지표가 높게 나오면 렌더 경로를 확인해야 합니다.

**오탐 2 — "Landing의 `h1` 앞에 `h3`가 있다"**

파일 순서로는 `h3`(L38)가 `h1`(L390)보다 앞섭니다. 그러나 L38은 `FeatureCard` **컴포넌트 정의** 안이고, 렌더 위치는 features 섹션 내부입니다. 런타임 순서는 `h1 → h2 → h3×3 → h2 → …`로 정상입니다.

> 교훈: 헤딩 순서는 **파일 순서가 아니라 렌더 순서**로 봐야 합니다. 컴포넌트가 같은 파일에 정의되면 정적 분석이 어긋납니다.

## 7. 잔여 작업 종료 (2026-11-03)

오너 결정: **사전은 `locales/*.json`에 통합** · **간격은 기존 단계로 스냅**. A·H·G를 모두 처리했고

### 7-1. A — i18n 342키 이전

차단 요소가 없음을 먼저 확인했습니다. `server.mjs`에 Sylphio는 sitemap 3줄뿐이라 **SSR 의존이 없고**
(§6의 "§4-2와 묶어 판단" 메모는 과한 우려였습니다), 세 지면이 모두 `const d = TRANSLATIONS[locale] || TRANSLATIONS['ko']`
동일 패턴이라 **`t('sylphio.<ns>')`이 의미가 같습니다**(없으면 ko fallback). 사전은 함수·JSX·템플릿 보간 0건의 순수 JSON입니다.

| 항목 | 결과 |
| :--- | ---: |
| 이전 키 | **342** (114 × 3로케일) |
| 지면 JSX 감소 | **−452줄** (643→454 · 438→290 · 235→120) |
| 변경된 호출부 | **0** (`d.xxx` 103개 전수 대조 — 3로케일 모두 해석 확인) |
| 정리한 죽은 키 | 11키 × 3로케일 = 33 |
| index 번들 | gzip **+17.7KB** (즉시 로드) |
| Sylphio 청크 | **−46.5KB** |

`tocLabel`의 3항 분기도 흡수했습니다 — "레이아웃 상수라 콘텐츠 사전과 역할이 다르다"는 기존 근거는
사전이 공용 파일로 옮겨진 뒤 성립하지 않습니다. 반면 **문장 중간에 링크가 박힌 리치 텍스트 2곳은
JSX로 남깁니다**(문자열 사전에 HTML을 담을 수 없습니다). `SCENARIOS`는 UI 로케일이 아니라
**데모 화자 언어**(`jp` 키)라 대상이 아닙니다.

### 7-2. H — 실제 규모는 보고서의 4배였다

보고서는 "Sylphio 49 + ReLearn 41"로 적었는데 전역 실측은 **776건**이었습니다. 성격이 셋으로 갈립니다.

| 부류 | 건수 | 처리 |
| :--- | ---: | :--- |
| 토큰과 값이 같은 유채색 | **351** | `color-mix(in srgb, var(--token) N%, transparent)`로 전환 |
| 흰/검 오버레이 | 325 | 대상 아님 — 대응 토큰이 없어 문법만 바꿔도 얻는 게 없다(`task_backlog` §3-8) |

처리 중 드러난 것: `AdminDashboard.css`가 **`:root`를 재선언**하고 상태색(`--admin-green/orange/red`)이
