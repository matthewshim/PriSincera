## 0. 이 문서의 위치

2026-11-13 기획서 7종 재점검에서 드러난 문제 — **MVP가 1인·무자본·제로상태 치고 무겁고(특히 경험담), 출시 시점에 확실히 작동하는 차별점은 "먼저 찾아옴" 하나** — 에 대한 **범위 축소 결정**이다. 본 문서는 *무엇을 넣고 뺄지*를 정하고, **구축 상세(아키텍처·API·작업 분해·일정)는 [mvp_build_plan.md](mvp_build_plan.md)** 에 둔다.

> **한 줄**: 경험담·모더레이션을 뒤로 미루고, 동반 메시지(F-5)는 **전체 유지**한 채 **`기록 → 먼저 찾아옴 → 동반(4톤·AI) → 다시 보기`** 를 MVP로 세워 **가장 싸게·혼자서 핵심을 증명**한다.

## 1. 배경 — 왜 지금 범위를 줄이나

| 문제 | 설명 |
| :--- | :--- |
| **범위 과대** | 기존 MVP = 기능 10·화면 10. 경험담(제출→수동검수→매칭→기여)이 가장 무거움 — 모더레이션·익명화·신고·PII 검수 **파이프라인 전체** 요구. |
| **가장 공들일 곳이 가장 비어 있음** | 경험담은 **콜드스타트가 리스크 #1**. 초기 경험담 0이면 루프 ③이 공허 → 노력 대비 체감 최저. |
| **모트 집중** | 확실히 작동하는 **먼저 찾아옴 + 동반(AI)** 를 먼저 증명. 경험담은 그 위에 얹는다. |
| **정체성 먼저 원칙** | 드리프트 하드룰 5("정체성 서기 전 연동·수익화 금지")와 동일 정신. |

## 2. 핵심 결정 — "얇은 루프"(동반 F-5는 전체)

```
① 결정 기록 ─▶ ② 먼저 찾아옴(시간규칙) ─▶ ③ 동반 메시지(4톤·AI) ─▶ ④ 다시 보기(회고)
 (사용자 입력)   (이메일 + 웹푸시)          (템플릿+체험AI+BYOK)       (상태 전이)
```

- **경험담(F-6/7/8)은 루프에서 분리** → M2 이후. "아직 비슷한 이야기가 없어요"조차 노출하지 않음(기능 부재).
- **동반 메시지(F-5)는 전체 구현**(템플릿 4톤 + 체험 AI Groq + BYOK) — 오너 결정(2026-11-13). AI가 핵심 체감이라 축소하지 않음.
  → 이에 따라 **R2(Groq 무료 ZDR·캡 검증)가 M1 착수 전 선행(블로킹) 조건**으로 승격한다.
- 결과 MVP = **모더레이션 0·경험담 콜드스타트 0**으로 설 수 있는 코어. 외부 AI는 **체험(Groq·ZDR·캡) + BYOK**로 통제([security_spec §6](security_spec.md)).

## 3. 범위 대조 (Before → After)

### 3-1. 기능 (F-1 ~ F-10)

| F | 기능 | 기존 | **재범위** | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| F-1 | 가입·온보딩 | In | **In(간소화)** | 경험담 동의 제거, 알림·조용시간 동의만 |
| F-2 | 결정 기록 | In | **In** | |
| F-3 | 홈(타임라인+다가온 알림) | In | **In** | |
| F-4 | 먼저 찾아옴(시간규칙) | In | **In** | 이메일+웹푸시 — MVP의 심장 |
| F-5 | 동반 메시지 4톤 + AI | In | **In(전체: 템플릿+체험AI+BYOK)** | **R2 선행 검증 필요** |
| F-6 | 경험담 매칭·노출 | In | **Out → M2** | |
| F-7 | 경험담 작성·제출 | In | **Out → M2** | |
| F-8 | 경험담 검수(모더레이션) | In | **Out → M2** | |
| F-9 | 다시 보기·결과 기록 | In | **In** | "경험담 기여 CTA"만 숨김(M2 복귀) |
| F-10 | 알림 센터·설정 | In | **In** | |

→ **In 7 / M2로 3.** 핵심 루프·AI 온전, 커뮤니티 레이어만 분리.

### 3-2. 화면 (S-1 ~ S-10)

- **유지(7)**: S-1 온보딩(간소) · S-2 홈 · S-3 결정 기록 · S-4 결정 상세(동반 4톤+AI, **경험담 매칭 리스트 제거**) · S-5 다시 보기 · S-8 알림 센터 · S-9 설정
- **보류 → M2(4)**: S-6 경험담 상세 · S-7 경험담 둘러보기 · S-7-W 경험담 작성 · S-10 검수 큐
- **IA**: 하단 탭 **4 → 3**(`홈 · 기록하기 · 나`). `[경험담]` 탭 제거.

### 3-3. 데이터 모델

| 컬렉션 | 처리 |
| :--- | :--- |
| `users`, `decisions`(+`messages`), `decisionEvents`, `notifications`, **`aiUsage`(체험 AI 캡)** | **사용** |
| `stories`, `storiesPublic`, `storyFeedback`, `moderationLogs` | 정의 유지·미사용(M2) |

> M0 `waymarkModel.mjs`에 전 컬렉션 정의됨 → **스키마 변경 없음**. 미사용분 "M2" 주석만. `firestore.rules` deny-all 유지(서버 경유).

## 4. 증명 게이트 — 무엇이 되면 ③ 경험담을 얹는가

| 신호 | 기준 | 의미 |
| :--- | :--- | :--- |
| 먼저찾아옴 응답률 | ≥ 40% | 모트 작동 |
| 결정 기록 지속 | 주당 ≥ 1건(활성자) | 기록 습관 |
| 회고 완료율 | retro 도래분 ≥ 50% 결과 기록 | 루프 닫힘 |
| 정성 | "덜 외로웠다/곁에 있었다" 체감 | North Star 질적 근거 |

## 5. 일정 리셋 (2026-11-13 기준)

| 단계 | 범위 | 착수 | 승격 게이트 |
| :--- | :--- | :--- | :--- |
| **M1-0 선행검증** | R2(Groq ZDR·캡)·FCM·BYOK CORS 확인 | **지금** | 전 항목 확인(블로킹) |
| **M1 얇은 루프 알파** | 기록·홈·먼저찾아옴·**동반 F-5 전체**·회고·알림/설정 | M1-0 직후 | 내부 dogfooding + §4 |
| **M1.5 소수 베타** | 초대 5~10인, §4 계측 | M1 후 | §4 충족 |
| **M2 경험담** | 제출·수동검수·매칭 | 게이트 통과 후 | 시드·검수 가동 |
| **M3 → GA** | 안정화·KPI·공개 | M2 후 | 안정성·KPI |

> **고정 GA 일자(2027-03) 제거** — "증명 후 공개".

## 6. 지표 영향

- **North Star 유지**(경험담 없이 성립). **M1 KPI**: 4주 리텐션·먼저찾아옴 응답률·회고 완료율. **M2로 이동**: 경험담 기여율·"도움됐어요".

## 7. 리스크 · 완화

| 리스크 | 완화 |
| :--- | :--- |
| 경험담 없이 차별점 약해 보임 | 모트 = 먼저 찾아옴 + 동반 AI에 집중 |
| 대외 비전 축소 오해 | 소개 페이지·Builder's Log는 풀 비전 유지 — 재범위는 **내부 빌드 순서** |
| 경험담 되붙이기 비용 | 스키마·Rules **지금 유지** → M2 UI·파이프라인만 추가 |
| **R2 미검증(Groq ZDR)** | **M1 선행 블로킹** — 불가 시 F-5 AI 설계 재조정(소액 유료 or BYOK 우선) |
