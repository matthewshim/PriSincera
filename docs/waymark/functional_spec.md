## 0. 읽는 법 (ID 체계)

| 접두 | 의미 | 예 |
| :--- | :--- | :--- |
| **F-n** | 기능(Feature) | F-2 결정 기록 |
| **S-n** | 화면(Screen) | S-3 결정 상세 |
| **AC** | 수용 기준(Acceptance Criteria) — "이게 되면 완료" | AC-2.1 |
| **T-n** | 동반 톤(템플릿) | T-1 위로 |

- 전역 규칙: 다크 셀레스철 테마([design_system](../core/design_system.md)) 재사용. 토큰·§9 컴포넌트 규범 준수. 모바일 우선(360~430px), 데스크톱은 중앙 컬럼(max 480~560px 앱 셸).
- 언어: ko 기본, en·ja 대응(문자열 전부 i18n 키). 보이스 톤은 §8.
- 원칙 하드룰: **AI는 대신 결정하지 않는다**. 모든 AI 응답·CTA는 선택을 사용자에게 돌려준다.

## 1. 사용자 역할 · 권한

| 역할 | 권한 |
| :--- | :--- |
| **사용자(user)** | 본인 결정·대화·알림 CRUD, 경험담 제출/열람(승인분), 본인 경험담 관리 |
| **모더레이터(moderator)** | 경험담 검수 큐 접근, 승인/반려, 신고 처리 |
| **관리자(admin)** | 모더레이터 권한 + 시드 콘텐츠·공지·사용자 관리 |

> MVP 모더레이터·관리자 = 오너 1인. 전용 간이 어드민(웹). 상세 권한은 [system_architecture §8](system_architecture.md).

## 2. 정보 구조(IA) · 내비게이션

**하단 탭 4개**(모바일) / 좌측 레일(데스크톱):

```
[홈]        S-2 결정 타임라인 + 다가온 먼저찾아옴
[기록하기]   S-3 결정 기록(캡처) — 중앙 플로팅 + 탭
[경험담]     S-7 경험담 둘러보기
[나]        S-9 설정·알림·프로필
```
- 전역 진입: 결정 기록(어디서든 + 버튼) → S-3
- 알림(종) → S-8 알림 센터
- 결정 카드/알림 → S-4 결정 상세

## 3. 기능 명세 (F-1 ~ F-10)

> 각 기능: **목적 · 사용자 스토리 · 흐름 · 수용 기준(AC) · 엣지/에러**.

---

### F-1 · 가입 · 온보딩

- **목적**: 첫 결정을 남기기까지의 마찰 최소화 + 알림·조용시간 동의 확보.
- **스토리**: "앱을 열면, 길게 설명 듣지 않고도 첫 결정을 남기고 왜 '먼저 찾아오는지' 이해한다."
- **흐름**: 소셜 로그인(Google·Apple) → 3스텝 가치 소개(먼저·내게 맞게·살아있게) → **이메일 수신 동의**(먼저찾아옴 기본 채널) + (선택)웹푸시 권한·**홈 화면 설치 안내**(iOS는 설치 시 푸시) + 조용시간 기본값(22:00~08:00) → (선택)첫 결정 유도.
- **수용 기준**
  - AC-1.1 소셜 로그인 성공 시 `user_profiles` 자동 생성(locale=브라우저 기준).
  - AC-1.2 웹푸시 거부·iOS 미설치여도 **먼저찾아옴은 이메일로 도달**(+인앱). 온보딩 완료 가능.
  - AC-1.3 조용시간 기본 22:00~08:00, 이후 설정에서 변경 가능.
  - AC-1.4 온보딩은 **1회성**(완료 플래그), 재방문 시 S-2로 직행.
- **엣지**: 권한 거부/나중에 → 설정에서 재요청 가능. 로그인 실패 → 재시도 안내(에러 원인 표기).

### F-2 · 결정 기록 (캡처)

- **목적**: "그 순간의 결정과 마음"을 30초 안에 남긴다.
- **스토리**: "큰 결정을 내린 직후, 복잡한 입력 없이 핵심만 빠르게 남긴다."
- **입력 필드**

| 필드 | 타입 | 필수 | 비고 |
| :--- | :--- | :--- | :--- |
| 제목 | text(≤80) | ✅ | "팀을 옮기기로 했다" |
| 상황/맥락 | textarea | ✅ | 자유 서술 |
| 선택지 | string[] | ✕ | 고려한 옵션들(태그 입력) |
| 내가 내린 결정 | text | ✅ | 하나로 요약 |
| 감정 태그 | enum multi | ✅ | 불안·후련·설렘·두려움·확신·혼란(6종, §7-감정셋) |
| 도메인 | enum single | ✅ | 커리어·팀/조직·제품/일·관계·돈·건강·기타(§7-도메인셋) |
| 중요도 | 1~3 | ✅ | 먼저찾아옴 주기에 영향(§6) |
| 되돌릴 수 있나 | bool | ✕ | 회고 프레이밍에 활용 |

- **흐름**: + 버튼 → 폼(단일 스크롤) → 저장 → S-4 결정 상세로 이동 + **즉시 T+0 지지 메시지(템플릿)** 노출 + `decision_events` 스케줄 생성(§6).
- **수용 기준**
  - AC-2.1 필수 필드 미입력 시 저장 불가(인라인 검증).
  - AC-2.2 저장 즉시 T+0 지지 메시지가 상세에 생성된다.
  - AC-2.3 저장 즉시 체크인/회고 이벤트가 중요도 규칙(§6)대로 `scheduled`로 생성된다.
  - AC-2.4 임시저장(초안) 지원 — 앱 이탈 후 복귀 시 복원.
- **엣지**: 오프라인 저장 → 로컬 큐 후 동기화. 아주 긴 맥락 → 서버 길이 제한(예 4,000자) 안내.

### F-3 · 홈 (결정 타임라인 + 다가온 먼저찾아옴)

- **목적**: "지금 돌봐야 할 결정"과 "다가온 안부"를 한 화면에.
- **구성**: 상단 **다가온 먼저찾아옴**(오늘 응답할 체크인/회고) → 아래 **결정 타임라인**(최신순, 상태 뱃지: 진행 중·회고 대기·마무리).
- **수용 기준**
  - AC-3.1 응답 대기 이벤트가 있으면 상단 카드로 강조.
  - AC-3.2 타임라인은 무한 스크롤·최신순, 도메인/상태 필터.
  - AC-3.3 빈 상태(결정 0) → "첫 결정을 남겨보세요" + 예시.
- **엣지**: 로딩 스켈레톤, 네트워크 에러 시 재시도.

---

### F-4 · 먼저 찾아옴 (시간 규칙 알림)

- **목적**: 서비스가 **먼저** 안부를 물어 "혼자가 아님"을 만든다.
- **메커니즘**: 결정 생성 시 규칙(§6)대로 `decisionEvents` 생성 → **Cloud Scheduler→Cloud Run Job**(기존 패턴)이 도래·조용시간 밖 이벤트에 **이메일(기존 엔진) + 웹푸시(FCM) + 인앱 + 결정 상세 동반 메시지** 생성.
- **이벤트 종류**: `nudge_support`(T+0 지지) · `checkin`(T+2~3일 안부) · `midterm`(T+2주 중간 회고) · `retro`(T+1달 결과·회고).
- **수용 기준**
  - AC-4.1 조용시간 내 도래 이벤트는 조용시간 종료 후 **첫 가능 시각**으로 지연 발송(스킵 아님).
  - AC-4.2 동일 결정·동일 종류 이벤트는 **중복 발송 금지**(멱등).
  - AC-4.3 사용자가 2회 연속 미응답 시 이후 체크인 **빈도 감쇠**(§6-3).
  - AC-4.4 푸시 미허용 사용자는 인앱 배지로만 전달, 기능 동일.
  - AC-4.5 결정이 `closed`면 잔여 이벤트 자동 취소.
- **엣지**: 푸시 토큰 만료 → 인앱 폴백 + 재구독 유도. 타임존은 사용자 프로필 기준.

---

### F-5 · 동반 메시지 (4톤) + AI 체험 (Groq 무료·캡 → BYOK)

- **목적**: 결정의 그 순간, 필요한 '결'로 곁에 있는다. **대신 결정하지 않는다.** **규칙·템플릿 기본 + 학습 안 하는 무료 티어(Groq·ZDR) 체험 AI(엄격 캡·₩0) + 쿼터 소진·미BYOK 시 템플릿 폴백 → 지속은 BYOK.** (공급자 하드룰 [security_spec §6](security_spec.md))
- **4톤**: T-1 위로 · T-2 조언 · T-3 응원 · T-4 정리 (톤별 메시지 라이브러리 §5).
- **흐름**: 결정 상세(S-4) 동반 영역 → 감정·이벤트 규칙으로 **톤 자동 선택** + 사용자가 톤 전환 가능 → 해당 톤 **템플릿 메시지(변수 치환)** 노출. 먼저찾아옴 메시지도 여기 누적. 자유 입력은 **사용자 메모**로 저장(LLM 응답은 MVP 밖).
- **수용 기준**
  - AC-5.1 각 결정은 하나의 동반 타임라인(메시지 누적).
  - AC-5.2 톤 전환 시 메시지 톤이 명확히 바뀐다.
  - AC-5.3 모든 템플릿은 **결정을 사용자에게 돌려주는 문장**으로 닫힌다(§5-하드룰).
  - AC-5.4 위기 신호 키워드 감지 시 **전문 도움 안내 템플릿** 노출(일반 조언 금지).
  - AC-5.5 LLM 호출 없음 → 즉시 렌더(네트워크 지연 없음).
- **BYOK(지속·심화)**: 사용자가 자기 키 연결 시 LLM 대화. **키 입력→검증→공급자/티어 경고**(Gemini 무료=학습), 브라우저(IndexedDB·암호화) 보관·**서버 미경유·무로그·무동기화**, 원클릭 삭제. 상세 [security_spec §6](security_spec.md).

### F-6 · 경험담 매칭 · 노출

- **목적**: "같은 갈림길을 지난 사람"의 이야기를 그 순간에.
- **흐름**: 결정 상세(S-4)에서 해당 결정의 **도메인 + 감정 태그 + 키워드**로 승인된 경험담 Top-N(기본 3) 노출.
- **수용 기준**
  - AC-6.1 매칭은 **도메인 일치 우선 → 감정 태그 겹침 → 의미 유사도** 순 가중(§7-2).
  - AC-6.2 승인(`approved`) 경험담만 노출. 본인 제출 pending은 "검토 중"으로 본인에게만.
  - AC-6.3 매칭 0건이면 "아직 비슷한 이야기가 없어요 — 당신이 첫 이야기가 될 수 있어요"(기여 유도).
  - AC-6.4 각 경험담에 "도움됐어요/아니에요" 피드백(지표·랭킹 반영).
- **엣지**: 키워드 미태깅 경험담은 도메인·감정 매칭만. 신고 버튼(→ 검수 큐 재진입).

### F-7 · 경험담 작성 · 제출

- **목적**: 회고를 마친 결정을 **익명 경험담으로 기여** → 커뮤니티 자산·선순환.
- **진입**: (1) 다시 보기(S-5) 완료 후 "이 경험 나눌래요?" (2) 경험담 탭에서 직접 작성.
- **입력**: 제목, 본문(겪은 일·배운 점), 도메인(결정에서 자동 채움), 감정 태그, **익명 여부(기본 익명)**, 원본 결정 연결 여부(비공개 — 매칭 품질용).
- **수용 기준**
  - AC-7.1 제출 시 상태 `pending` → 검수 큐로. 사용자에겐 "검토 후 공개" 안내.
  - AC-7.2 익명 제출은 작성자 식별정보가 노출 경로 어디에도 포함되지 않는다(§9-프라이버시).
  - AC-7.3 PII 자동 감지 경고(이름·연락처·회사 특정 등) + 수정 유도.
  - AC-7.4 본인은 내 경험담 상태(검토/공개/반려+사유) 확인·철회 가능.
- **엣지**: 반려 시 사유 + 재제출 경로. 길이 가이드(≤ 4,000자).

---

### F-8 · 경험담 검수 (모더레이션)

- **목적**: 품질·안전·프라이버시 보장(공개 자산이므로).
- **흐름**: 제출 → **사람 검수 큐(S-10)** → 승인/반려(+사유). 승인 시 `storiesPublic` 뷰 생성 → 매칭 풀 편입. *(제출 급증 시 AI 선필터는 추후 보강)*
- **수용 기준**
  - AC-8.1 신고·위험 키워드 플래그 항목은 큐 상단 우선.
  - AC-8.2 승인 전까지 어떤 사용자에게도 노출 안 됨.
  - AC-8.3 모든 검수 액션은 `moderation_logs`에 기록(감사).
  - AC-8.4 신고된 공개 경험담은 재검수 큐로 복귀, 필요 시 즉시 비공개.
- **엣지**: 대량 제출 레이트리밋. 반려 사유 템플릿(프라이버시/품질/주제 외/안전).

---

### F-9 · 다시 보기 · 결과 기록

- **목적**: 지난 결정을 다시 마주해 **그때 vs 지금**을 비교하고 패턴을 학습.
- **진입**: `retro` 먼저찾아옴 또는 결정 상세의 "다시 보기".
- **구성**: 그때의 기록(감정·맥락) 요약 → 지금 질문("결과는? 지금 마음은?") → **결과 기록**(잘됨/아쉬움/진행 중 + 메모 + 지금 감정) → 패턴 태그(선택) → 경험담 기여 유도(F-7).
- **수용 기준**
  - AC-9.1 결과 기록 시 결정 상태 `revisited` 또는 `closed`로 전이.
  - AC-9.2 "그때 감정 → 지금 감정" 변화가 시각적으로 대비된다.
  - AC-9.3 회고 완료 → 경험담 기여 CTA 노출(강요 아님).
- **엣지**: 아직 결과가 없으면 "진행 중"으로 저장, 다음 주기 재방문.

---

### F-10 · 알림 센터 · 설정

- **목적**: 먼저찾아옴 통제권을 사용자에게(알림 피로 방지).
- **설정 항목**: 푸시 on/off, **조용시간**(시작·종료), 체크인 **주기 프리셋**(촘촘/보통/느슨), 중요도별 on/off, 언어(ko/en/ja), 계정·데이터(내보내기·삭제).
- **수용 기준**
  - AC-10.1 조용시간·주기 변경은 즉시 향후 스케줄에 반영(기존 `scheduled` 재계산).
  - AC-10.2 알림 센터는 읽음/안읽음, 항목 탭 시 해당 결정 상세로.
  - AC-10.3 계정 삭제 시 본인 데이터 완전 삭제, 익명 경험담은 분리 보존 여부 선택(§9).
- **엣지**: 데이터 내보내기(JSON) 비동기 생성 후 다운로드 링크.

## 4. 화면 명세 (S-1 ~ S-10)

> 공통: 다크 테마, 하단 탭(모바일), 상단 앱바(로고+종+아바타). 상태 = **빈/로딩/에러/정상**. 컴포넌트는 design_system §9 글래스 카드·버튼·fs 토큰.

| ID | 화면 | 핵심 컴포넌트 | 주요 상태·인터랙션 |
| :--- | :--- | :--- | :--- |
| **S-1** | 온보딩 | 3스텝 캐러셀, 권한 프롬프트, 조용시간 피커 | 스텝 진행, 권한 허용/거부 분기 |
| **S-2** | 홈 | 다가온-먼저찾아옴 카드, 결정 타임라인 카드, 필터칩, + FAB | 빈 상태, 무한스크롤, 당겨 새로고침 |
| **S-3** | 결정 기록 | 단일 스크롤 폼, 감정 칩 멀티선택, 도메인 셀렉트, 중요도 세그먼트 | 인라인 검증, 임시저장, 저장→S-4 |
| **S-4** | 결정 상세 | 결정 요약 헤더, **동반 메시지(톤 스위처·템플릿)**, 경험담 매칭 리스트, 다시보기 진입 | 톤 전환, 메모 작성, 경험담 피드백 |
| **S-5** | 다시 보기/회고 | 그때↔지금 대비 뷰, 결과 세그먼트, 감정 비교, 기여 CTA | 결과 저장→상태 전이 |
| **S-6** | 경험담 상세 | 본문, 도메인·감정 태그, 도움됐어요, 신고 | 익명 표기, 공유(선택) |
| **S-7** | 경험담 둘러보기 | 도메인/감정 필터, 카드 리스트, 작성 FAB | 검색·필터, 빈 상태 |
| **S-7-W** | 경험담 작성 | 폼(제목·본문·태그·익명 토글), PII 경고 | 제출→검토 안내 |
| **S-8** | 알림 센터 | 알림 리스트(읽음/안읽음), 종류 아이콘 | 탭→결정 상세, 전체 읽음 |

## 5. 동반 톤 설계 (T-1 ~ T-4 · 템플릿 기본 + 체험 AI/BYOK)

공통 하드룰(모든 톤 템플릿):
- **대신 결정하지 않는다.** 템플릿은 선택을 사용자에게 돌려주는 문장으로 닫는다.
- ReLearn식 "성장 코치·과제 부여" 톤 금지. Waymark은 **정서 동반자**.
- 한국어 기본, 짧고 담백. 과장·클리셰 금지.
- 안전(AC-5.4): 위기 신호 키워드 감지 → **전문 도움 안내 템플릿**으로 전환, 일반 조언 중단.

| 톤 | 트리거(규칙) | 역할 | 템플릿 메시지 예(변수 {제목}) | 닫는 문장 예 |
| :--- | :--- | :--- | :--- | :--- |
| **T-1 위로** | 감정=불안·두려움·혼란, 결정 직후 | 마음을 다독임 | "{제목}, 쉽지 않은 결정이었죠. 지금 마음이 복잡해도 괜찮아요." | "지금은 이 마음을 알아주는 걸로 충분해요." |
| **T-2 조언** | 사용자 '정리 도움' 요청, 결정 전 | 갈래를 짚는 질문 | "선택지 중 가장 걸리는 건 무엇인가요? 놓친 관점은 없을까요?" | "어느 쪽이 더 맞을지, 결국 당신이 더 잘 알아요." |
| **T-3 응원** | 결정 직후·실행 국면, 감정=확신·설렘 | 밀고 갈 힘 | "{제목}, 당신답게 내린 결정이에요. 첫 한 걸음만 가볍게." | "그 결정, 밀고 나가봐요. 곁에 있을게요." |
| **T-4 정리** | 감정=혼란, 생각 엉킴 | 구조화 질문 | "머릿속을 선택지 / 기준 / 마음 셋으로 나눠볼까요?" | "정리는 도왔지만, 결정은 당신 몫으로 남겨둘게요." |

> 톤 선택: 감정·이벤트 규칙으로 자동 + 사용자 전환(톤 스위처). 템플릿은 **i18n 리소스(ko/en/ja × 톤 × 이벤트)**로 관리하며 변수 치환만 — **LLM 호출 전무**. AI 심화(BYOK)는 [system_architecture §10](system_architecture.md).

## 6. 먼저 찾아옴 스케줄 규칙

### 6-1. 기본 타이밍(중요도 보통=2 기준)

| 이벤트 | 시점 | 목적 | 기본 모드 |
| :--- | :--- | :--- | :--- |
| nudge_support | T+0 (저장 즉시) | 결정을 지지 | T-1 또는 T-3 |
| checkin | T+2일 | 안부·실행 점검 | T-1/T-3 |
| midterm | T+14일 | 중간 회고 | T-4 |
| retro | T+30일 | 결과 기록·회고 | T-4 → F-9 |

### 6-2. 중요도·주기 프리셋 보정

| 중요도 | checkin | midterm | retro |
| :--- | :--- | :--- | :--- |
| 1 (가벼움) | T+3일 | 생략 | T+21일 |
| 2 (보통) | T+2일 | T+14일 | T+30일 |
| 3 (무거움) | T+1일 | T+10일 | T+30일, +90일 1회 추가 |

- 주기 프리셋(설정): **촘촘**(×0.7) / **보통**(×1.0) / **느슨**(×1.5) 배수.
- 조용시간(AC-4.1): 도래가 조용시간 내면 종료 후 첫 가능 시각으로 지연.

### 6-3. 감쇠·종료
- 연속 2회 미응답 → 다음 checkin 1회 건너뜀(감쇠). 3회 → 해당 결정 능동 알림 중단(수동 열람만).
- 결정 `closed` → 잔여 이벤트 취소.

## 7. 분류 체계 · 매칭 규칙

### 7-1. 고정 분류셋(초기)
- **도메인(7)**: 커리어 · 팀/조직 · 제품/일 · 관계 · 돈 · 건강 · 기타
- **감정(6)**: 불안 · 후련 · 설렘 · 두려움 · 확신 · 혼란
> 분류셋 변경은 본 문서 개정으로만(데이터 일관성). i18n 키로 관리.

### 7-2. 경험담 매칭 랭킹(F-6)
`score = 0.6·도메인일치 + 0.3·감정태그 겹침 + 0.1·키워드 겹침` (임베딩 없음, 초기 가중치·튜닝 대상). 동점 시 최신·"도움됐어요" 비율 우선. 쿼리는 [system_architecture §5](system_architecture.md).

### 7-3. 검수 체크리스트(F-8)
① PII 없음(이름·연락처·회사·특정 가능 정보) ② 혐오·차별·공격 없음 ③ 자해·위법 조장 없음 ④ 주제 적합(결정 경험) ⑤ 최소 품질(의미 있는 서술). 하나라도 위반 → 반려(사유 템플릿).

## 8. 카피 · 보이스 톤

- **결(voice)**: 담백·따뜻·과장 없음. "~해야 한다" 금지, "~해볼까요/곁에 있을게요" 지향.
- **원칙 문구**(상시 노출): "결정은 당신의 몫 — Waymark은 대신 정하지 않아요."
- **먼저찾아옴 예시 카피**:
  - checkin: "그 결정, 어떻게 지내고 있어요?"
  - retro: "한 달 전 그 갈림길, 지금 돌아보면 어때요?"
- **빈 상태**: "첫 결정을 남겨보세요. 작은 선택이어도 괜찮아요."
- 금지: 성과·생산성 압박, 판단·훈계, 거짓 위로 클리셰("다 잘될 거예요" 남발).

## 9. 비기능 요구

| 영역 | 요구 |
| :--- | :--- |
| 성능 | 첫 상호작용까지 < 3s(모바일 4G), 화면 전환 체감 즉시. PWA 오프라인 기록 큐. |
