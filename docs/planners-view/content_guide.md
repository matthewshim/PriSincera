## 1. 이 섹션의 글은 무엇인가 (🔒 규범)

**만드는 일에 대한 관점과 판단**을 기록합니다. 제작 기록이 아닙니다.

| | **Planner's View** | **Builder's Log** |
| :--- | :--- | :--- |
| 무엇을 | 관점·판단 (무엇을·누구를 위해·왜 지금) | 만든 기록 (어떻게 만들었나) |
| 증거 | 경험과 논지 | 커밋(Key Shipments)·챕터 |
| 1인칭 | **필자 개인**(실명 바이라인) | 제작 주체 |

판단이 애매하면 **"커밋으로 증명되는 글인가"** 를 묻습니다. 그렇다면 Builder's Log입니다.

## 2. 글 구조 규격 (🔒 규범)

### 2-1. 마크다운 골격

```markdown
(리드 문단 — 헤딩 없이 시작. 글 전체의 문제의식을 담는 1문단)

## 첫 번째 소제목
(2~4문단)

## 두 번째 소제목
...

## 맺으며
(1~2문단)
```

- **H1(`#`)을 쓰지 않는다.** 제목은 `plannersViewMeta.json`의 `title`이 페이지 히어로로 렌더한다. 본문에 H1을 두면 h1이 둘이 된다.
- **리드 문단은 헤딩 없이** 시작한다. 목차에 잡히지 않으면서 글의 문제의식을 세우는 자리다.
- 소제목은 **H2(`##`)만** 사용한다. H3는 목차를 2단으로 만들어 짧은 에세이에는 과하다. 필요하면 쓰되 남용하지 않는다.
- **H2는 5~7개**. 3개 이하면 목차가 무의미하고, 8개 이상이면 에세이가 아니라 문서가 된다.
- 마지막 섹션은 **`## 맺으며`**(en `## In closing` / ja `## むすびに`)로 통일한다. 연재를 관통하는 리듬이다.
- **Revision History 섹션 금지.** 발행 아티클에는 넣지 않는다 — 빌드 게이트가 차단한다.

### 2-2. 소제목 작성법

소제목이 곧 우측 목차가 되고, 목차만 읽어도 논지가 흐르도록 쓴다.

- **문장형으로 쓴다.** `복원과 학습은 층위가 다릅니다`(O) / `회복탄력성`(X)
- 명사 나열형 제목은 문서의 문법이지 에세이의 문법이 아니다.
- 목차를 위에서 아래로 읽었을 때 **논증의 뼈대**가 보이는지 확인한다.
- **[열거형 예외 — v1.1]** 글이 `N가지 …`를 병렬로 다루는 **열거형 구조**라면, 문장형 대신 **병렬 라벨**을 허용한다(예: `첫째, 문제를 향해 묻는 '왜' — 문제를 다시 쓰는 훈련`). 목차에서 N개 항목이 한눈에 대비되는 편이 규격의 취지(목차만 읽어도 논지가 흐른다)를 더 잘 충족하기 때문이다. 다만 **라벨 형식을 글 안에서 섞지 않는다** — 열거형이면 전부 병렬 라벨로, 아니면 전부 문장형으로 간다.

### 2-3. 분량

| 항목 | 기준 |
| :--- | :--- |
| 한국어 본문 | **2,000~3,500자**(공백 제외) — 6분 내외 |
| 영문 | 1,000~1,500단어 |
| 문단 | 3~6문장. 한 문단에 한 논점 |

짧으면 SNS 포스트와 구분되지 않고, 길면 완독률이 급락한다. 현재 발행분은 ko 2,600~2,800자 수준이며 이 대역을 기준선으로 삼는다.

### 2-4. 강조·인용

- **볼드(`**`)는 문단당 1회 이하.** 남용하면 강조가 사라진다.
- 블록인용(`>`)은 남의 말을 인용할 때만 쓴다. 필자 자신의 핵심 문장은 본문에 두고 **`pullQuote` 메타**로 뽑아 올린다(히어로 아래 리드 인용으로 렌더).
- 코드 블록·표는 이 섹션의 문법이 아니다. 필요하면 Builder's Log에 쓸 글이 아닌지 먼저 의심한다.

## 3. 시리즈 운영 (🔒 규범)

이 섹션의 글은 **시리즈에 속하거나, 단독 글**이다.

### 3-1. 시리즈 정본 — `src/data/plannersViewSeries.json`

시리즈 제목·설명은 **한 곳에만** 둔다. 각 글의 메타에 제목을 복사하면 표기가 갈라진다.

```json
[
  {
    "id": "cheap-execution",
    "title":       { "ko": "실행이 값싸진 시대", "en": "...", "ja": "..." },
    "description": { "ko": "…연작의 문제의식 1~2문장…", "en": "...", "ja": "..." }
  }
]
```

### 3-2. 글에서의 참조 — `plannersViewMeta.json`

```json
"series": { "id": "cheap-execution", "order": 1 }
```

- `order`는 **연재 순서**다(1부터). 발행일 순서와 어긋나도 `order`가 우선한다.
- `series`를 생략하면 단독 글로 취급되어 목록의 **단독 글** 묶음에 들어간다.
- 같은 `id` 안에서 `order`가 중복되면 안 된다.

### 3-3. 언제 새 시리즈를 여는가

- **같은 전제에서 갈라져 나온 글**이면 기존 시리즈에 `order`를 이어 붙인다.
- 전제가 다르면 새 `id`를 만든다. 한 시리즈가 5~6편을 넘어가면 주제가 흐려지지 않았는지 점검한다.
- 시리즈가 완결되면 별도 표시를 하지 않는다. 연재는 열린 채로 둔다.

## 4. 메타 문안 작성법

`plannersViewMeta.json`의 각 필드는 렌더되는 자리가 다르다. 자리를 알고 쓴다.

| 필드 | 렌더 위치 | 작성 기준 |
| :--- | :--- | :--- |
| `title` | 히어로 h1 · 목록 카드 · 브라우저 탭 · 공유 카드 | **30자 내외**. 길면 히어로에서 3줄로 깨진다. 연재는 제목 문법을 승계하면 시리즈로 읽힌다(예: `X가 흔해진 시대, Y가 귀해진 시대`) |
| `subtitle` | 히어로 부제 · 목록 카드 | 제목이 못 담은 **논지의 방향**을 한 문장으로. `A — B` 형태로 앞에 주제, 뒤에 결론 실마리 |
| `description` | 검색 스니펫 · 공유 카드 설명 | **150~250자.** 앞 150자가 잘려 노출되므로 **핵심 논거를 앞에** 둔다. 제목을 반복하지 않는다 |
| `pullQuote` | 히어로 아래 리드 인용 | 글에서 **한 문장만 남는다면** 그것. 본문에 실제로 있는 문장이어야 한다 |
| `tags` | 히어로 태그 칩 | **영문 표기 통일**, 3~4개. 시리즈 전체를 관통하는 태그 1개를 공유하면 묶임이 드러난다(예: `Organization`) |
| `readMinutes` | 메타 라인 | 수동 산정 — 아래 §4-1 |
| `accent` | 배지·목차 활성·히어로 후광 | 브랜드 4색만. **현재 섹션 전체 lavender(`#C7D2FE`) 고정** — 편수가 적은 동안은 글별 분화보다 섹션 정체성 일관이 낫다 |
| `author` | 바이라인 | `role`은 소속 조직명을 넣지 않는다. §5 참조 |

### 4-1. `readMinutes` 산정

```
ko 본문 공백 제외 글자수 ÷ 450   (한국어 정독)
en 단어수 ÷ 220
→ 둘 중 큰 값을 반올림
```

본문이 바뀌면 다시 계산한다. 자동 산정을 두지 않은 이유는 [publishing_guide §5](publishing_guide.md)에 있다.

## 5. 필자 표기와 고지 (🔒 규범)

- **실명 바이라인**을 쓴다. 1인칭 관점 글이므로 화자가 드러나야 한다.
- `author.role`에 **소속 조직명을 넣지 않는다.** 현직을 특정하면 글이 회사 공식 입장으로 오독될 위험이 커진다. 직무 성격만 표기한다(예: `웹서비스 총괄 · 프로덕트 리더`).
- 본문 하단의 **개인 견해 고지**(`plannersView.disclaimer`)는 제거하지 않는다. 언어팩에 있으며 모든 글에 자동 노출된다.
- 현직 경험을 근거로 쓸 때는 **조직을 특정하지 않고 기간·역할로만** 서술한다(예: `최근 4년 남짓 게임 회사의 웹서비스를 총괄하면서`).

## 6. 다국어 (🔒 규범)

- **ko 원문 + en·ja 동시 발행.** 로케일 파일이 없으면 한국어로 폴백되지만, 그 상태를 정상으로 두지 않는다.
- 세 벌의 **H2 개수와 문단 수가 일치**해야 한다. 번역에서 문단을 합치거나 쪼개지 않는다 — 목차가 언어별로 갈라진다.
- 고유명사·개념어는 원어 병기를 허용한다(예: `안티프래질(antifragile)`).
- 인용한 인물의 발언은 **해당 언어의 실제 표현**으로 옮긴다. 한국어 번역을 다시 기계적으로 영역하지 않는다.

## 7. 발행 전 체크리스트 (Self-QA)

- [ ] 본문에 H1이 없다 (제목은 메타가 렌더)
- [ ] 리드 문단이 헤딩 없이 시작한다
- [ ] H2가 5~7개이고, 목차만 읽어도 논지가 흐른다
- [ ] 마지막 섹션이 `맺으며`다
- [ ] Revision History 섹션이 없다
- [ ] ko 2,000~3,500자 대역이다
- [ ] ko·en·ja 세 벌의 H2 개수·문단 수가 같다
- [ ] `pullQuote`가 본문에 실제로 있는 문장이다
- [ ] `description` 앞 150자에 핵심 논거가 들어 있다
- [ ] `series.order`가 기존 글과 중복되지 않는다
- [ ] `readMinutes`를 본문 기준으로 재산정했다
- [ ] `author.role`에 소속 조직명이 없다
- [ ] 태그가 영문이고 시리즈 공통 태그를 포함한다
