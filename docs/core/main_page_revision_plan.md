## 3. Phase 1 — 신뢰: 별자리 천문 수치 (최우선)

### 3-1. 화면의 수치가 전부 순번 산술이다

`StarField.jsx:899-901`에서 **네 값 모두** 배열 순번 `ci`로 만들어집니다.

```js
const raHours = Math.floor(ci * 2).toString().padStart(2, '0');
const decDegs = (ci * 7 - 35 >= 0 ? '+' : '') + (ci * 7 - 35);
const distLy  = 350 + ci * 85;
const appMag  = (1.1 + ci * 0.15).toFixed(1);
// 출력: RA {raHours}h 15m / DEC {decDegs}° | Dist: ~{distLy} ly | Mag: {appMag}
```

분은 **`15m` 고정 문자열**입니다. 열두 별자리가 2시간·7도·85광년·0.15등급 간격으로
가지런히 늘어섭니다. **"Sincerity, Prioritized."를 내건 지면의 그럴듯한 가짜 숫자**이고,
별자리는 별 하나가 아니므로 '거리'와 '등급'을 별자리 단위로 쓰는 것 자체가 성립하지 않습니다.

**조치** — 대표 별(α) 기준으로 밝히고, 값은 데이터에 둡니다.

```js
{
  name: 'Leo', sub: 'The Lion', symbol: (현행 값 유지),
  ra: '10h 40m', dec: '+14°',
  alpha: { bayer: 'α', name: 'Regulus', mag: 1.35, distLy: 79 },
  cx: 0.06, cy: 0.42, stars: [...], lines: [...],
}
```

표시: `RA 10h 40m / DEC +14° · α Regulus · Mag 1.35 · 79 ly`

**검수 규칙**: 중심 좌표는 IAU 공표 경계 기준, 거리는 Hipparcos/Gaia 시차 기준으로 확인합니다.
외부 문서의 표는 **출처 없는 초안이므로 인용하지 않고 재조사**합니다. 오차가 큰 값은 `~`를 붙여
근삿값임을 드러냅니다.

### 3-2. 바이어 문자도 데이터가 아니라 순번이다 (외부 문서가 스치고 지나간 것)

`StarField.jsx:836·857`:

```js
const GREEK_DESIGNATIONS = ['α','β','γ','δ','ε','ζ','η','θ','ι','κ','λ','μ'];
const bayerLetter = GREEK_DESIGNATIONS[starIndex % GREEK_DESIGNATIONS.length];
```

`stars` 배열 **순서**에 그리스 문자를 차례로 붙입니다. 그런데 배열 순서는 밝기 순이 아니라
**선을 잇기 좋은 순서**입니다. 주석에 실제 별이 적혀 있어 대조가 됩니다.

| 별자리 | 주석의 실제 순서 | 배열 인덱스 | 렌더 결과 | 판정 |
| :--- | :--- | :--- | :--- | :--- |
| Aries | γ→β→α→41Ari | 3=γ 2=β 1=α 0=41Ari | 0에 α, 1에 β, 2에 γ | **완전 역순** |
| Libra | α→β→γ→υ, α→σ | 0=α 1=β 2=γ 3=σ 4=υ | 3에 δ, 4에 ε | 앞 3개만 맞음 |
| Cancer | β→δ→α, δ→γ→ι | 0=α 1=β 2=γ 3=δ 4=ι | 4에 ε | 앞 4개만 맞음 |

**별자리마다 우연히 맞거나 틀립니다.** Aries는 `α`가 가장 어두운 41 Ari에 붙습니다.

**조치** — `stars` 각 항목을 `[x, y]`에서 `{ xy, bayer, name }`으로 올리고 렌더러는 데이터를
읽습니다. `lines`가 쓰는 인덱스는 그대로라 **선 모양은 바뀌지 않습니다**.

### 3-3. 재발 방지 게이트

`ci/`에 데이터 정합 검사를 둡니다.

- 열두 항목 전부 `ra` · `dec` · `alpha.{bayer,name,mag,distLy}` 보유
- `stars[].bayer` 전부 존재하고 한 별자리 안에서 중복 없음

## 5. Phase 3 — 접근성·시맨틱

### 5-1. 메가메뉴 `h3` 6개가 `h1`보다 앞선다

`Header.jsx` 294·335·360·395·418·443의 `<h3 className="bento-card-title">`가
DOM에서 지면 `h1`보다 먼저 나옵니다(WCAG 1.3.1).

스타일은 **클래스 셀렉터**(`.bento-card-title`)가 걸고 있고 `margin`도 명시돼 있어,
`<h3>`을 `<p>`로 바꾸면 **시각은 그대로**입니다.

> **오탐 주의**: Sylphio 감사에서 "`h3`가 `h1`보다 앞" 판정이 **컴포넌트 정의 순서**를
> 본 오탐이었던 전례가 있습니다. 이번 건은 `Header`가 앱 최상단에서 실제로 먼저
> 렌더되므로 **런타임 순서상 진짜**입니다.

### 5-2. 카운터 초기값이 0이다

`JourneySection.jsx:23` `useState(0)` — DOM 최초값이 `0+`라 크롤러와 스크린리더에는
"0+ YEARS"로 읽힙니다.

**조치** — 시각은 그대로 세고, 기계에는 최종값을 줍니다.

```jsx
<div className="stat-number">
  <span aria-hidden="true">{count}<span className="stat-plus">{suffix}</span></span>
  <span className="u-sr-only">{target}{suffix} {label}</span>
</div>
```

- `.u-sr-only` 유틸이 **없으므로 `index.css`에 신설**합니다(전역 0건 확인).
- `prefers-reduced-motion`이면 애니메이션 없이 최종값을 그립니다. 전역 CSS 규칙은
  CSS 애니메이션만 덮으므로 **훅 안에서 `matchMedia`로 직접 확인**해야 합니다
  (2026-11-03 StarField에서 같은 교훈).

### 5-3. 장식 canvas에 `aria-hidden`이 없다

`StarField.jsx:1057`과 `ConstellationAssembly.jsx:536`(`energy-canvas`) 둘 다 없습니다.
순수 장식이므로 `aria-hidden="true"`를 답니다.

### 5-4. 토글 버튼이 상태를 알리지 않는다

`aria-pressed`가 **전역 0건**입니다. 음악 버튼(`Header.jsx:260`)과 STAR MAP 버튼은
켬/끔 상태를 갖는데 스크린리더에 전달되지 않습니다.

> **외부 문서 부분 반려**: 같은 항목에서 "라벨·툴팁 추가"를 요구했지만, 음악
> `aria-label="Toggle music"`·언어 `aria-label="Select Language"`는 **이미 있고**,
> STAR MAP 버튼에는 `<span class="ctrl-tooltip">STAR MAP</span>`이 들어 있어
> **접근명과 툴팁이 모두 이미 있습니다**. 남는 것은 `aria-pressed`뿐입니다.

### 12-7. 연차 표기 (D-2 결정 2026-11-04)

2007년 3월 시작이라 현재 **19년 8개월**입니다. `20+`는 아직 사실이 아닙니다.

| 자리 | 결정 | 이유 |
| :--- | :--- | :--- |
| 숫자 카운터 | `20+` → **`20`** (`+` 제거) | 19.67은 20으로 반올림되는 값이다. `+`만 빼면 '넘는다'는 주장이 사라진다 |
| 한국어 산문 | **"20년 가까이"** | 오너가 이미 쓰는 표현이고 지금 정확하다. 2027.03에 "20년"으로 자연 승계 |
| 영문 | **`Two decades of`** | `20+ years`를 피한다 |
| 일문 | **`20年近く`** | ko와 같은 뜻 |

`20여 년`은 채택하지 않습니다 — 접미사 `-여(餘)`가 "그 수를 **넘음**"이라
`20+`와 같은 방향의 넘침 표기입니다. 별자리 가짜 수치를 최우선 교정 대상으로 올린 지면에서
다른 칸의 같은 종류 반올림을 허용하면 기준이 무너집니다.

**발행 글 처리**: 아티클에 `20년 넘게` **5건**, `20여 년` 2건, `20년 가까이` 1건이
이미 나가 있어 서로 어긋납니다. **소급 수정하지 않습니다** — 2027년 3월이면 "넘게"가
사실이 되어 자연 해소되고, 발행본 수정은 그 자체로 이력에 남습니다.
대신 **앞으로 쓸 글이 연차를 직접 쓰지 않도록** `planners-view/content_guide.md`에 규칙을 둡니다.

**나머지 두 칸**: `50+ Projects`는 집계 단위, `5+ Countries`는 국가 목록 확인이 남았습니다.
남미(LATAM) 진출과 글로벌 IP 서비스로 근거는 잡혔습니다.

### 13-1. 현직을 간접적으로 드러내기 (D-7 관련)


### 13-3. D-4 — `Sincerity`로 통일 (적용 완료)

`conceptCard3.subtitle`을 3로케일 모두 `Sincera` → **`Sincerity`** 로 바꿨습니다.
`Attitude / Priority / Sincerity` — 셋 다 보통명사로 맞춰집니다.

*"성실함(Sincerity)이라는 태도로 인턴에서 정규직 제안을 받으며 커리어 시작"* 이므로,
경험 5단 1단의 태도 문장을 `성실함`으로 맞추면 **브랜드 이름이 커리어의 출발점에서 나왔다**는
사실이 드러납니다. 카드 라벨을 조어로 비틀어 설명하는 것보다 이쪽이 셉니다.

### 13-4. D-5 — Canvas 모션 감쇠: 정지 프레임 1장

`prefers-reduced-motion: reduce`일 때 **한 프레임을 그린 뒤 루프를 멈춥니다.**

- **완전 정지**(아무것도 그리지 않음)는 배경이 검게 비어 지면의 세계관이 사라집니다.
- **현행 유지**는 규범 위반입니다 — 전역 CSS 규칙은 CSS 애니메이션만 덮습니다.
- 정지 프레임은 별과 별자리가 그대로 보이되 **움직이지 않아** 요구를 충족합니다.

구현: `draw()` 진입부에서 `matchMedia('(prefers-reduced-motion: reduce)').matches`이면
`drawFrame()`을 한 번 호출하고 `requestAnimationFrame`을 재예약하지 않습니다.
별똥별·자동 하이라이트도 함께 끕니다. 설정이 바뀌면 `change` 이벤트로 재개합니다.

### 13-5. D-6 — 사전 렌더링: 빌드 시 생성되는 정적 폴백

외부 문서의 C안(정적 폴백)을 택하되, **이중 관리를 없애는 형태**로 합니다.

- `index.html`에 본문을 손으로 박지 않습니다 — 로케일 JSON과 내용이 갈립니다.
- 대신 `ci/`에 스크립트를 두고, **빌드 후** `src/locales/ko.json`과 `src/data/seoMeta.mjs`에서
  `h1` · 소개 문장 · 서비스 5개 링크를 뽑아 `dist/index.html`의 `#root` 안에 심습니다.
  React가 마운트하면서 덮어쓰므로 사용자에게는 보이지 않고, 크롤러에는 본문이 보입니다.
- **출처가 하나**라 내용이 갈리지 않고, 서비스가 늘어도 자동으로 따라옵니다.

**§4-2(언어별 SSR 본문)와는 분리합니다.** 그쪽의 대기 결정 4건은 URL 전략에 관한 것이고,
이 폴백은 그 결정과 무관하게 지금 넣을 수 있습니다. 장기적으로 A안(사전 렌더링)으로 옮길 때

- `플랫폼`을 풀어서 설명하므로 직함을 모르는 독자도 이해합니다.
- A안보다 설명적이라 우아함은 한 단계 덜합니다.

**A안을 권합니다.**

### 16-3. 3로케일 문안 (A안)

| | 문안 |
| :--- | :--- |
| ko | 회사에서는 글로벌 서비스가 설 무대를 만들고, 여기서는 제 것을 처음부터 만듭니다. |
| en | At work, I build the stage global services stand on. Here, I build my own. |
| ja | 会社ではグローバルサービスが立つ舞台をつくり、ここでは自分のものを一からつくります。 |

### 16-4. 기계에는 정확한 직함, 사람에게는 번역된 역할

둘을 나눕니다. 서로 다른 독자에게 서로 다른 것이 필요합니다.

```json
{
  "@type": "Person",
  "name": "Matthew Shim",
  "jobTitle": "Platform Director",
  "description": "20년 가까이 웹서비스를 만들어 온 플랫폼·프로덕트 리더. 글로벌 게임 서비스의 웹 기반을 총괄하며, PriSincera에서 AI와 함께 제품을 직접 설계하고 만든다."
}
```

- **`jobTitle`은 `Platform Director` 그대로** 둡니다. 구조화 데이터는 검색엔진이 읽고
  LinkedIn과 대조되는 값이므로 **정확해야 하고, 우아할 필요가 없습니다.**
- **지면에는 직함을 쓰지 않습니다.** 사람이 읽는 자리에는 §16-2의 번역된 역할만 둡니다.
- 이 분리가 "타이틀보다 경험"이라는 결정과 **검증 가능성**을 동시에 지킵니다.

### 16-5. 어디에 어떻게 놓이는가

| 자리 | 내용 |
| :--- | :--- |
| Hero 정체성 한 줄 | §16-2 A안 |
| JOURNEY 5단 마지막 | 현재형 종결로 재직 중임을 전달(§13-1) |
| JSON-LD | `jobTitle: "Platform Director"` (§16-4) |
| CONNECT | `자문 · 협업 제안을 환영합니다.`(§13-2) |

**`디렉터`·`총괄`·`리더`라는 말이 지면 어디에도 나오지 않습니다.**
그런데도 읽는 사람은 그 자리의 일이라는 것을 압니다 — 하는 말이 그 자리의 말이기 때문입니다.
