## 3. Phase 1 — 신뢰: 별자리 천문 수치 (최우선)

### 3-1. 화면의 수치가 전부 순번 산술이다

`StarField.jsx:899-901`에서 **네 값 모두** 배열 순번 `ci`로 만들어집니다.

```js
const raHours = Math.floor(ci * 2).toString().padStart(2, '0');
const decDegs = (ci * 7 - 35 >= 0 ? '+' : '') + (ci * 7 - 35);
const distLy  = 350 + ci * 85;
const appMag  = (1.1 + ci * 0.15).toFixed(1);
// 출력: RA {raHours}h 15m / DEC {decDegs}° | Dist: ~{distLy} ly | Mag: {appMag}
```

분은 **`15m` 고정 문자열**입니다. 열두 별자리가 2시간·7도·85광년·0.15등급 간격으로
가지런히 늘어섭니다. **"Sincerity, Prioritized."를 내건 지면의 그럴듯한 가짜 숫자**이고,
별자리는 별 하나가 아니므로 '거리'와 '등급'을 별자리 단위로 쓰는 것 자체가 성립하지 않습니다.

**조치** — 대표 별(α) 기준으로 밝히고, 값은 데이터에 둡니다.

```js
{
  name: 'Leo', sub: 'The Lion', symbol: (현행 값 유지),
  ra: '10h 40m', dec: '+14°',
  alpha: { bayer: 'α', name: 'Regulus', mag: 1.35, distLy: 79 },
  cx: 0.06, cy: 0.42, stars: [...], lines: [...],
}
```

표시: `RA 10h 40m / DEC +14° · α Regulus · Mag 1.35 · 79 ly`

**검수 규칙**: 중심 좌표는 IAU 공표 경계 기준, 거리는 Hipparcos/Gaia 시차 기준으로 확인합니다.
외부 문서의 표는 **출처 없는 초안이므로 인용하지 않고 재조사**합니다. 오차가 큰 값은 `~`를 붙여
근삿값임을 드러냅니다.

### 3-2. 바이어 문자도 데이터가 아니라 순번이다 (외부 문서가 스치고 지나간 것)

`StarField.jsx:836·857`:

```js
const GREEK_DESIGNATIONS = ['α','β','γ','δ','ε','ζ','η','θ','ι','κ','λ','μ'];
const bayerLetter = GREEK_DESIGNATIONS[starIndex % GREEK_DESIGNATIONS.length];
```

`stars` 배열 **순서**에 그리스 문자를 차례로 붙입니다. 그런데 배열 순서는 밝기 순이 아니라
**선을 잇기 좋은 순서**입니다. 주석에 실제 별이 적혀 있어 대조가 됩니다.

| 별자리 | 주석의 실제 순서 | 배열 인덱스 | 렌더 결과 | 판정 |
| :--- | :--- | :--- | :--- | :--- |
| Aries | γ→β→α→41Ari | 3=γ 2=β 1=α 0=41Ari | 0에 α, 1에 β, 2에 γ | **완전 역순** |
| Libra | α→β→γ→υ, α→σ | 0=α 1=β 2=γ 3=σ 4=υ | 3에 δ, 4에 ε | 앞 3개만 맞음 |
| Cancer | β→δ→α, δ→γ→ι | 0=α 1=β 2=γ 3=δ 4=ι | 4에 ε | 앞 4개만 맞음 |

**별자리마다 우연히 맞거나 틀립니다.** Aries는 `α`가 가장 어두운 41 Ari에 붙습니다.

**조치** — `stars` 각 항목을 `[x, y]`에서 `{ xy, bayer, name }`으로 올리고 렌더러는 데이터를
읽습니다. `lines`가 쓰는 인덱스는 그대로라 **선 모양은 바뀌지 않습니다**.

### 3-3. 재발 방지 게이트

`ci/`에 데이터 정합 검사를 둡니다.

- 열두 항목 전부 `ra` · `dec` · `alpha.{bayer,name,mag,distLy}` 보유
- `stars[].bayer` 전부 존재하고 한 별자리 안에서 중복 없음
- `StarField.jsx`에 `GREEK_DESIGNATIONS[` 패턴이 남아 있지 않음

**완료 기준**: 화면의 모든 수치가 데이터에서 오고, 공식으로 만든 값이 코드에 없다.

## 5. Phase 3 — 접근성·시맨틱

### 5-1. 메가메뉴 `h3` 6개가 `h1`보다 앞선다

`Header.jsx` 294·335·360·395·418·443의 `<h3 className="bento-card-title">`가
DOM에서 지면 `h1`보다 먼저 나옵니다(WCAG 1.3.1).

스타일은 **클래스 셀렉터**(`.bento-card-title`)가 걸고 있고 `margin`도 명시돼 있어,
`<h3>`을 `<p>`로 바꾸면 **시각은 그대로**입니다.

> **오탐 주의**: Sylphio 감사에서 "`h3`가 `h1`보다 앞" 판정이 **컴포넌트 정의 순서**를
> 본 오탐이었던 전례가 있습니다. 이번 건은 `Header`가 앱 최상단에서 실제로 먼저
> 렌더되므로 **런타임 순서상 진짜**입니다.

### 5-2. 카운터 초기값이 0이다

`JourneySection.jsx:23` `useState(0)` — DOM 최초값이 `0+`라 크롤러와 스크린리더에는
"0+ YEARS"로 읽힙니다.

**조치** — 시각은 그대로 세고, 기계에는 최종값을 줍니다.

```jsx
<div className="stat-number">
  <span aria-hidden="true">{count}<span className="stat-plus">{suffix}</span></span>
  <span className="u-sr-only">{target}{suffix} {label}</span>
</div>
```

- `.u-sr-only` 유틸이 **없으므로 `index.css`에 신설**합니다(전역 0건 확인).
- `prefers-reduced-motion`이면 애니메이션 없이 최종값을 그립니다. 전역 CSS 규칙은
  CSS 애니메이션만 덮으므로 **훅 안에서 `matchMedia`로 직접 확인**해야 합니다
  (2026-11-03 StarField에서 같은 교훈).

### 5-3. 장식 canvas에 `aria-hidden`이 없다

`StarField.jsx:1057`과 `ConstellationAssembly.jsx:536`(`energy-canvas`) 둘 다 없습니다.
순수 장식이므로 `aria-hidden="true"`를 답니다.

### 5-4. 토글 버튼이 상태를 알리지 않는다

`aria-pressed`가 **전역 0건**입니다. 음악 버튼(`Header.jsx:260`)과 STAR MAP 버튼은
켬/끔 상태를 갖는데 스크린리더에 전달되지 않습니다.

> **외부 문서 부분 반려**: 같은 항목에서 "라벨·툴팁 추가"를 요구했지만, 음악
> `aria-label="Toggle music"`·언어 `aria-label="Select Language"`는 **이미 있고**,
> STAR MAP 버튼에는 `<span class="ctrl-tooltip">STAR MAP</span>`이 들어 있어
> **접근명과 툴팁이 모두 이미 있습니다**. 남는 것은 `aria-pressed`뿐입니다.

### 12-7. 연차 표기 (D-2 결정 2026-11-04)

2007년 3월 시작이라 현재 **19년 8개월**입니다. `20+`는 아직 사실이 아닙니다.

| 자리 | 결정 | 이유 |
| :--- | :--- | :--- |
| 숫자 카운터 | `20+` → **`20`** (`+` 제거) | 19.67은 20으로 반올림되는 값이다. `+`만 빼면 '넘는다'는 주장이 사라진다 |
| 한국어 산문 | **"20년 가까이"** | 오너가 이미 쓰는 표현이고 지금 정확하다. 2027.03에 "20년"으로 자연 승계 |
| 영문 | **`Two decades of`** | `20+ years`를 피한다 |
| 일문 | **`20年近く`** | ko와 같은 뜻 |

`20여 년`은 채택하지 않습니다 — 접미사 `-여(餘)`가 "그 수를 **넘음**"이라
`20+`와 같은 방향의 넘침 표기입니다. 별자리 가짜 수치를 최우선 교정 대상으로 올린 지면에서
다른 칸의 같은 종류 반올림을 허용하면 기준이 무너집니다.

**발행 글 처리**: 아티클에 `20년 넘게` **5건**, `20여 년` 2건, `20년 가까이` 1건이

## 13. 오너 결정 반영 (2026-11-04 2차)

### 13-1. 현직을 간접적으로 드러내기 (D-7 관련)

오너 요청: "현재 플랫폼 디렉터로 근무 중인데, 너무 노골적으로 말고 세련되게."

**직책어를 쓰지 않고 '범위'와 '시제'로 말합니다.** 디렉터임을 드러내는 것은 직함이 아니라
**무엇을 걱정하는가**입니다. 실무자는 기능을 말하고, 디렉터는 매출과 방향을 말합니다.

경험 5단의 마지막 단에서 **셋째 줄**이 그 일을 합니다(전문은 §12-4).

```
2022 — 현재   다시 게임으로, 이번엔 글로벌입니다
              (한 일 — §12-4 참조)
              지금은 웹서비스가 회사의 매출에 어떻게 기여할지를 설계하고 있습니다.
```

- `현재` + **현재형 종결**(`설계하고 있습니다`)이 재직 중임을 말합니다.
- 셋째 줄은 **오너의 LinkedIn 자기 서술을 거의 그대로** 옮긴 것입니다
  ("웹 서비스가 어떻게 회사의 매출과 미래 가치에 기여할 수 있는가"). 본인 문장이라 톤이 어긋나지 않습니다.
- `총괄`·`디렉터`·`리더` 같은 직책어를 쓰지 않아도, **매출 기여 설계는 그 자리의 일**이라
  읽는 사람이 알아봅니다.

**Hero에서는 현직을 말하지 않습니다.** "낮에는 회사, 밤에는 사이드" 같은 구도는 흔한 클리셰이고
퍼스널 브랜딩 사이트의 톤을 깎습니다. 현직은 JOURNEY에서 조용히 드러나면 충분합니다.

### 13-2. D-7 — 가용성이 아니라 협업

오너 판단: "개인 포트폴리오를 대체하는 퍼스널 브랜딩 사이트. 협업 제안은 받을 수 있겠다."

- **구직 신호를 넣지 않습니다** — `Open to work` 류의 표기는 사이트 성격과 맞지 않습니다.
- CONNECT 섹션에 **협업의 문만 엽니다**: 기존 문구에 한 줄을 더합니다.
  `자문 · 협업 제안을 환영합니다.`
- 병행 사실은 §13-1의 현재형이 이미 전달하므로 **따로 설명하지 않습니다.**

### 13-3. D-4 — `Sincerity`로 통일 (적용 완료)

`conceptCard3.subtitle`을 3로케일 모두 `Sincera` → **`Sincerity`** 로 바꿨습니다.
`Attitude / Priority / Sincerity` — 셋 다 보통명사로 맞춰집니다.

**브랜드 의도는 다른 자리에서 더 강하게 살립니다.** LinkedIn 첫 경력의 자기 요약이
*"성실함(Sincerity)이라는 태도로 인턴에서 정규직 제안을 받으며 커리어 시작"* 이므로,
경험 5단 1단의 태도 문장을 `성실함`으로 맞추면 **브랜드 이름이 커리어의 출발점에서 나왔다**는
사실이 드러납니다. 카드 라벨을 조어로 비틀어 설명하는 것보다 이쪽이 셉니다.

### 13-4. D-5 — Canvas 모션 감쇠: 정지 프레임 1장

`prefers-reduced-motion: reduce`일 때 **한 프레임을 그린 뒤 루프를 멈춥니다.**

- **완전 정지**(아무것도 그리지 않음)는 배경이 검게 비어 지면의 세계관이 사라집니다.
- **현행 유지**는 규범 위반입니다 — 전역 CSS 규칙은 CSS 애니메이션만 덮습니다.
- 정지 프레임은 별과 별자리가 그대로 보이되 **움직이지 않아** 요구를 충족합니다.

구현: `draw()` 진입부에서 `matchMedia('(prefers-reduced-motion: reduce)').matches`이면
`drawFrame()`을 한 번 호출하고 `requestAnimationFrame`을 재예약하지 않습니다.
별똥별·자동 하이라이트도 함께 끕니다. 설정이 바뀌면 `change` 이벤트로 재개합니다.

### 13-5. D-6 — 사전 렌더링: 빌드 시 생성되는 정적 폴백

외부 문서의 C안(정적 폴백)을 택하되, **이중 관리를 없애는 형태**로 합니다.

- `index.html`에 본문을 손으로 박지 않습니다 — 로케일 JSON과 내용이 갈립니다.
- 대신 `ci/`에 스크립트를 두고, **빌드 후** `src/locales/ko.json`과 `src/data/seoMeta.mjs`에서
  `h1` · 소개 문장 · 서비스 5개 링크를 뽑아 `dist/index.html`의 `#root` 안에 심습니다.
  React가 마운트하면서 덮어쓰므로 사용자에게는 보이지 않고, 크롤러에는 본문이 보입니다.
- **출처가 하나**라 내용이 갈리지 않고, 서비스가 늘어도 자동으로 따라옵니다.

**§4-2(언어별 SSR 본문)와는 분리합니다.** 그쪽의 대기 결정 4건은 URL 전략에 관한 것이고,
이 폴백은 그 결정과 무관하게 지금 넣을 수 있습니다. 장기적으로 A안(사전 렌더링)으로 옮길 때
이 스크립트는 걷어냅니다.

**완료 기준**: `curl https://www.prisincera.com/`의 결과에 `h1`, 소개 문장, 서비스 5개 링크가 포함된다.

### 13-6. `50+ Projects` — 삭제, 그리고 통계 블록 자체를 재검토

오너 확인: "이전 제작 시 임의로 러프하게 넣은 것 같다."

선택지 셋입니다.

| 안 | 내용 | 평가 |
| :--- | :--- | :--- |
| A | **통계 블록 제거**, 경험 5단이 그 자리를 대신 | **권고.** 숫자 세 개보다 "무엇을 겪었는가" 다섯 줄이 더 많은 것을 말한다. 클리셰도 함께 사라진다 |

**A를 권합니다.** 경험 5단이 들어오면 통계 블록은 같은 말을 숫자로 한 번 더 하는 것이 됩니다.

## 16. D-1 — 현 직책을 사이트 정체성에 맞추는 안 (2026-11-04)

### 16-1. 문제를 다시 정의한다

`Platform Director`를 **번역하려 하면 실패합니다.** 영문 직함은 조직 내부의 언어라
회사 밖에서는 "그래서 무슨 일을 하는 사람인가"가 풀리지 않습니다. 게다가 회사명을 뺀 이유가
**"경력은 타이틀·회사가 아니라 경험"** 이었는데 직함만 크게 쓰면 그 결정과 어긋납니다.

**직함을 말하지 말고, 직함이 하는 일을 사이트의 언어로 다시 씁니다.**

`Platform Director`가 실제로 하는 일은 **여러 서비스가 올라설 무대를 만들고 책임지는 것**입니다.
그리고 **PriSincera에서 하고 있는 일이 정확히 그것입니다.**

| 회사에서 | 이 사이트에서 |
| :--- | :--- |
| 8개 언어·3개 권역 통합 서비스 기반 | 3로케일 체계 · SSR |
| 결제 수단 31종 연동 | 디자인 시스템 정본(v7.2) · 지표 게이트 29종 |
| 나라마다 다른 규제를 지키는 회원 체계 | 5개 서비스가 그 위에 올라가 있음 |

**이 사이트 자체가 직함의 증거입니다.** 그러니 직함을 선언할 필요가 없습니다 —
**같은 일을 두 곳에서 하고 있다는 구조만 보여주면 독자가 알아서 읽습니다.**

### 16-2. Hero 정체성 한 줄 — 3안

**A안 — 대구형 (권고)**

- `무대를 만든다`가 **platform의 뜻을 그대로 옮긴 말**입니다. 직함어를 한 번도 쓰지 않습니다.

  ① **본인의 어휘다** — 발행 글에 이미 "글로벌 **무대**에서 실패는 한 가지 얼굴로 오지 않습니다"가 있습니다.
  반면 `바닥`의 유일한 용례는 "올라온 것은 **바닥**인데"로 **최저값을 뜻하는 부정 표현**입니다.
  ② **사이트 세계관과 맞는다** — 별·빛·프리즘의 지면에서 `바닥`은 낮은 말이고 `무대`는 같은 층위의 말입니다.
  ③ **역할이 선명해진다** — `무대에 선다`는 과시지만 **`무대를 만든다`는 겸손**입니다.

## 17. 구현 중 발견 — 홈만 SSR을 타지 않고 있었다 (2026-11-04)

§4-1에 "`index.html`만 고치면 `server.mjs`가 덮어써 라이브가 바뀌지 않는다"고 적었습니다.
**홈에 한해 틀렸습니다. 정반대였습니다.**

`express.static(DIST_DIR)`의 **자동 index 제공**이 켜져 있어 `/` 요청이 정적 미들웨어에서
바로 응답됐습니다. 그래서 홈은 **SSR 메타 파이프라인을 아예 타지 않았고**, `index.html`의
정적 메타만 썼습니다. 반면 `/relearn` 같은 경로는 파일이 없어 catch-all로 내려가 `seoMeta.mjs`를 씁니다.

| 경로 | 메타 출처 (교정 전) |
| :--- | :--- |
| `/` | `index.html` 정적 메타 — SSR 미경유 |
| 그 외 전부 | `seoMeta.mjs` (SSR 주입) |

**출처가 둘로 갈려 있었고, 갈린 쪽이 하필 홈이었습니다.** 메타를 두 곳 모두 고친 조치는
결과적으로 맞았지만, 제가 댄 근거는 틀렸습니다.

**조치**: `express.static`에 `index: false`를 줘서 `/`도 catch-all로 내려가게 했습니다.
이제 모든 경로가 같은 파이프라인을 탑니다. `dist`의 `index.html`은 하나뿐이라 다른 디렉터리의
자동 제공이 깨질 일이 없고, 정적 자산(`/favicon.ico` 등)은 그대로 200입니다.

**검증**(로컬 서버 실측):

| 경로 | JSON-LD |
| :--- | :--- |
| `/` | `Person` + `WebSite` 1개 |
| `/planners-view/{slug}` | `Article` 1개 (이중 주입 없음) |

이 발견이 **P7-2(사전 렌더링)의 전제도 바꿉니다** — 정적 폴백을 `dist/index.html`에 심으려면
홈이 그 파일을 거쳐야 하는데, 이제 거칩니다. §13-5의 방향은 유효합니다.

### 19-2. P5-3 별자리 별 밝기 — 분포 실측으로 결정

배경 별은 `r = 0.25 + depth × 1.9`, `α = 0.05 + depth × 0.55`이고 `depth = rawDepth³`라
낮은 쪽으로 쏠립니다(30만 표본).

| | 중앙 | 85% | 90% | 95% |
| :--- | ---: | ---: | ---: | ---: |
| 반지름 | 0.49 | 1.42 | 1.64 | 1.88 |
| 투명도 | 0.12 | 0.39 | 0.45 | 0.52 |

구 별자리 값 `r 1.20 / α 0.28`은 **79·75 백분위**였습니다 — 배경 별 4분의 1이 더 밝아
패턴이 묻혔습니다. 외부 문서의 "배경 별과 비슷하다"는 절반만 맞았고, 실제로는
**가장 밝은 배경 별에 묻히는** 문제였습니다.

**`r 1.55 / α 0.42`로 올렸습니다** — 둘 다 **88 백분위**로 균형을 맞춰, 패턴은 읽히되
가장 밝은 배경 별과 경쟁하지 않습니다.

### 19-3. P5-5 배치 — "황도 호"가 답이 아니었다

화면을 가로지르는 진짜 황도 호는 **본문 카드와 히어로 로고를 관통**합니다.
중앙을 비우는 제약을 지키면 결국 **외곽 경로**가 됩니다. 그러니 할 일은 "호로 바꾸기"가 아니라
**외곽을 한 방향으로 연속해서 돌게 만드는 것**이었습니다. 구 구조는 상단 4 → 좌우 지그재그 4 →
하단 4라 측면에서 순서가 끊겼습니다.

`tier`를 더해 폭별로 접습니다 — 1=항상 · 2=`>=768px` · 3=`>=1600px`.

**바운딩 박스 실측**(별 퍼짐 + 라벨 폭 포함, 라벨은 렌즈 배율에 걸려 뷰포트와 무관하게 고정):

| 폭 | 표시 | 본문침범 | 화면밖 | 겹침 | (교정 전) |
| :--- | ---: | ---: | ---: | ---: | :--- |
| 2560 · 1920 · 1600 | 12 | 0 | 0 | 0 | 침범 1~2 |
| 1440 · 768 | 8 | 0 | 0 | 0 | 침범 8 / 화면밖 4 |
| 430 · 390 | 4 | 0 | 0 | 0 | **화면밖 8 · 겹침 5** |
| 1280 · 1024 · 375 | 8 / 4 | 2 | 0 | 0 | 침범 8 |

1280·1024·375의 침범 2건은 **본문(`--container` 1200)이 화면을 꽉 채우는 폭**이라
구조적으로 불가피합니다. 나머지는 전부 0입니다.

**외부 문서 오류 1건 추가**: "일부가 겹치거나 가려짐" — **데스크톱 상호 겹침은 원래 0건**이었습니다.
겹침은 모바일에만 있었고, 외부 문서는 데스크톱 1568px 실측이라 볼 수 없는 문제였습니다.

### 20-1. Hero 문구 — "회사에서는"이 걸렸다 (C안 채택)

- **퍼스널 브랜딩 지면의 첫 문장 주어가 남의 조직**이었습니다.
- 대비 축이 **장소**(회사 vs 여기)였습니다. 더 센 축은 대상이나 순서입니다.

| | |

### 20-2. 경험 5단과 연대기 카드의 구분 — 간격을 쟀더니 원인이 명확했다

**섹션 안에서 그 경계만 간격이 절반이었습니다.**

| 경계 | 교정 전 | 구분선 |
| :--- | ---: | :--- |
| 헤더 → 경험 5단 | 64px | 없음 |
| **경험 5단 → 연대기** | **32px** | 없음 |
| 연대기 → 각주 | 64px | 있음 |

가장 큰 전환점에 가장 좁은 간격이 걸려 있었습니다. `.journey-maker-note`가 이미 쓰는
헤어라인 패턴(`margin-top: --space-2xl` + `border-top`)을 **그대로 가져와** 리듬을 맞췄습니다.
새 장치를 만들지 않았고, `.timeline`에 `max-width`가 없어 선이 컨테이너 폭을 씁니다(§3-6).

### 20-3. 커리어가 밋밋했던 이유 — 장치가 0개였다

`.exp-item`은 `grid` 배치뿐이고 모션·시각 앵커가 하나도 없었습니다. 같은 무게의 5개가 반복돼
시선이 멈출 곳이 없는데, **바로 아래 연대기는 `--scroll-progress`로 선이 그려지고 마일스톤이
순차로 떴습니다.** 아래가 화려하니 위가 더 밋밋해 보인 것입니다.

**시각 — 연도 축 + 현재 단 강조**

- 연도 칼럼 경계에 세로 헤어라인, 각 항목에 점.
  **이 장치는 여기서 정당합니다.** §9-14 v6.9가 Work 섹션에 연대기 장치 복제를 금한 근거는
  *"동등한 5개를 훑는 색인이라 시간 순서가 뜻이 없다"* 였고, **경험 5단은 진짜 연대기**라
  정반대입니다. 같은 섹션 안 같은 의미의 장치이므로 복제가 아닙니다.
- 마지막 단만 **`--color-indigo`** — 연대기의 NOW 마일스톤과 **같은 색**이라
  "지금"이 섹션 안에서 한 색으로 읽힙니다. 색은 여기 한 곳에만 씁니다.

**모션 — 등장 리빌만 (스크롤 연동 없음)**

항목별 `IntersectionObserver`. 바로 아래가 이미 스크롤 연동이라 **여기까지 연동하면
한 섹션에 진행 막대가 둘이 되어 경쟁합니다**(11-03 "억지 통일" 판정과 같은 함정).
장치를 달리한 결과 **두 블록이 모션으로도 구분**되어 §20-2를 보강합니다.
감쇠 설정이면 처음부터 최종 상태로 둡니다.

**자가 발각**: `.journey-exp`를 두 번 선언해 `duplicate-selector` 게이트가 즉시 잡았습니다.
병합했습니다 — 게이트가 제 손을 막은 사례입니다.

### 20-4. 블록 끝 외부 링크 통일 (오너 지적 2026-11-04)

> "오픈소스 각주의 상단 라인과 하단 CTA 버튼을 '전체 경력은 LinkedIn에서'와 같은 형태로

**맞습니다. 그리고 두 규칙은 이미 7개 선언이 똑같았습니다** — 사실상 같은 컴포넌트에
박스만 덧댄 형태였습니다.

| | 경험 5단 | 각주 (교정 전) |
| :--- | :--- | :--- |
| 역할 | 블록 끝 외부 링크 | 블록 끝 외부 링크 |
| 형태 | mono 평문 링크 | **사각 버튼**(패딩·보더·리프트) |
| 색 | `--text-muted` → gold | gold 고정 |
| 아이콘 | `external` | `arrowRight` |

**조치** — 셋 다 경험 5단 쪽으로 맞췄습니다.

1. **한 규칙으로 통합**: `.exp-more, .maker-note-link`가 공통 형태를 공유하고,

2. **박스 제거**: 패딩·보더·리프트를 걷었습니다. **부수 효과로 §4-4 게이트 사각지대 1건이

3. **상단 선 제거**: 섹션에 전체 폭 헤어라인이 둘이면 과합니다. §20-2에서 연대기 경계에
   하나를 세웠고, 각주는 커리어가 아니라 **지면 자신에 대한 메모**라 조용히 흘러야 합니다.
   64px 간격으로 충분히 떨어집니다. 이제 섹션의 전체 폭 헤어라인은 **하나뿐**입니다.
4. **아이콘 통일**: 둘 다 `target="_blank"`로 나가는 외부 링크인데 아이콘이 달랐습니다.
   `external`로 맞췄습니다 — 같은 제스처는 같은 형태(§Icon 세트 규약).

### 20-5. 연도 축 좌우 여백 · 오픈소스 문구 (오너 지적 2026-11-04)

**(1) 축 좌우 여백이 3.8배 벌어져 있었다**

| | 교정 전 | 교정 후 |
| :--- | ---: | ---: |
| 연도 칼럼 | 7.5rem (120px) | **5.5rem (88px)** |
| 칼럼-본문 간격 | `--space-lg` (24px) | `--space-md` (16px) |
| 글자 끝 → 축 | **46px** | **10px** |
| 축 → 본문 | 12px | 8px |
| 비율 | **3.8 : 1** | **1.25 : 1** |

원인은 **좌측 정렬된 연도가 120px 칼럼에서 86px만 쓰고 34px을 남긴 것**입니다.
연도 문자열은 mono 11진폭 = `11.2px × (진폭 0.6em + 자간 0.1em)` ≈ **86px**이라
칼럼을 5.5rem로 줄이면 꼭 맞습니다.

**우측 정렬은 택하지 않았습니다.** 좌우가 8:8로 완전히 같아지지만 글자 시작이 34px 들어가
**섹션 좌단(제목·부제·통계)과 어긋납니다**. 좌측 리딩(§9-15)을 지키는 쪽을 골랐습니다.

축 기준값을 **`--exp-axis` 단일 변수**로 빼서 선·점·격자가 모두 그 값을 씁니다 —
세 곳에 같은 숫자를 적어 두면 다음에 또 갈립니다.

**(2) 오픈소스 설명 문단 삭제**

> "이 사이트의 전체 소스와 아키텍처는 오픈소스로 공개되어 있습니다." — 불필요한 정보

맞습니다. **링크 문구("오픈 소스 및 시스템 아키텍처 살펴보기")가 이미 같은 말을 합니다.**
문단·로케일 키 3개·CSS 규칙을 함께 걷었고, 섹션은 이제 경험 5단 끝의 LinkedIn 링크와
**같은 형태의 링크 하나**로 닫힙니다.

### 20-6. 육안 QA 환류 3차 — 축 여백·문구 길이·카드 아래 간격 (2026-11-04)

| 지적 | 실측 | 조치 |

### 20-7. 통계 블록 재설계 · NOW 카드 줄 수 (2026-11-04)

오너 지적: "경력을 비롯한 주요 수치 영역 디자인이 아쉽다 / NOW 카드만 2줄이다."
**재검토에서 제 앞 보고의 오류 2건과 못 봤던 결함 3건이 나왔습니다.**

**앞 보고 정정**

| 적었던 것 | 실제 |
| :--- | :--- |
| 모바일에서 3칸이 넘칠 수 있다 | **아니다.** `@media (max-width: 768px)`에 `flex-wrap: wrap`이 이미 있었다 |
| 줄 수를 글자 폭 16px로 추정 | **틀렸다.** 렌더 증거로 역산하니 본문 폭 309px에서 **54자가 2↔3줄 경계**다 |

**못 봤던 결함 3건 — 전부 제가 만든 것**

1. **스크린리더가 라벨을 두 번 읽었다.** `.u-sr-only`가 `"20 Years"`, `.stat-label`이 `"Years"` —
   11-04에 카운터 접근성을 고치면서 넣은 중복이다. 접근성을 고치려다 접근성을 깼다.
2. **카운트 중 숫자가 좌우로 튀었다.** 가운데 정렬 + 한 자리→두 자리에서 중심이 재계산된다.
3. **죽은 마크업·CSS.** suffix를 세 칸 모두 비운 뒤 `<span class="stat-plus">`는 항상 빈 요소였고
   `.stat-number .stat-plus` 규칙 4줄은 사문이었다.

**조치**

| # | 내용 |
| :--- | :--- |
| 정렬 | 가운데 → **좌측**. 섹션에서 이 블록만 가운데였다(§9-15 위반). 숫자 흔들림도 함께 사라진다 |
| 구조 | **라벨(eyebrow) → 숫자 → 캡션** 3단. 숫자↔라벨 간격 4px → 8px |
| 캡션 | `2007년부터` · `아시아·유럽·오세아니아·남미` · `한 권역 스토어프론트 기준` (3로케일) |
| 모션 | 지속을 **값에 비례**: `clamp(600, 값×45, 1400)ms`. 스텝 간격이 450ms→**150ms**(4), 58ms→45ms(31)로 고르게. 칸별 **100ms 스태거** |

**[왜 값을 스크롤에 연속으로 묶지 않았나]** 중간에 그쪽으로 기울었다가 접었다.
① 바로 아래 카드가 이미 스크롤 진행값을 쓴다 — 같은 성격의 장치가 둘이면 서로 약해진다.
② 스크롤 위치가 곧 경력이면 **스크롤을 멈춘 자리에서 경력도 멈춘다.** 호버로 다른 칸을
읽어도 막대는 가득 찬 채여야 한다.

다만 **되감기 자체는 넣었다**(오너 지적 2026-11-10). 카드는 올라가면 되감기는데 정거장만
1회 재생이면 한 섹션 안에서 규칙이 둘이 된다. 지면을 벗어나면 되감고 다시 내려오면 재생한다 —
값은 스크롤을 따라가지 않되 "올라가면 되돌아간다"는 같아진다.
막대는 되감을 때 `key`를 올려 **요소를 새로 만든다**: 폭 0으로 가는 역전이가 1.6초라,
그 사이에 다시 내려오면 중간에서 출발해 스윕이 잘린 것처럼 보인다.

**[이징을 뺀 이유]** ease-out이면 칸 간격이 255 → 302 → 393 → **950ms**로 벌어져
마지막 구간에서 멈춘 것처럼 보인다. 등속이면 400ms로 고르다.

| 쓰고 싶었던 것 | 대신 쓴 것 |

**[접근성·SEO]** 다섯 본문을 **전부 DOM에 남기고** 한 그리드 칸에 겹쳐 쌓았다 —

**[모션 — 활주에서 정박으로 (오너 지적 2026-11-10)]**

구 구조는 `transition-timing-function: linear` 한 줄이라 2007에서 현재까지 **한 번에
미끄러졌다.** 다섯 구간이 하나의 활주로 읽혀서, 정거장이 다섯이라는 사실이 막대에
드러나지 않았다. `linear()` 이징으로 구간마다 **이동 65% + 정박 35%** 를 넣었다.

| | 값 |
| :--- | :--- |
| 구간 | 400ms = 이동 260ms + 정박 140ms |
| 도달 지점 | 출력 0.25 / 0.5 / 0.75 / 1 을 각각 16.25% / 41.25% / 66.25% / 91.25% 에서 |
| 점 점등 | 구간 끝이 아니라 **이동이 끝나는 시각**(260 · 660 · 1060 · 1460ms). 구간 끝에 켜면 막대는 이미 서 있는데 점만 140ms 늦는다 |

키프레임을 새로 만들지 않았다(`keyframes-total` 여유 0) — **이징 함수 하나**로 끝난다.
단축 속성 대신 롱핸드를 쓴다: `linear()` 안의 쉼표가 `transition` 단축 파서를 헷갈리게 한다.
`MOVE_RATIO`(JSX)와 `linear()` 곡선(CSS)은 **같은 값이어야** 점과 막대가 같이 도착한다.


**[모션 재설계 — 1회 스윕 폐기, 스크롤 연동으로 (오너 결정 2026-11-10)]**

진입 1회 스윕으로 시작해 되감기·재생 트리거를 따로 맞추며 세 번 고쳤는데, 전부 **증상을

**[겹침 교정 — 기준 요소를 하나로 (오너 지적 2026-11-10)]**

"정거장이 다 끝나면 카드가 시작해야 하는데 겹친다." 재보니 **숫자 문제가 아니었다.**

구 구조는 정거장이 `.journey-stops`를, 카드가 `.timeline`을 각각 쟀다.
`useScrollProgress`는 **요소 자신의 높이와 위치**로 값을 내므로, 같은 0.12라도
두 블록에서 다른 스크롤 지점을 가리킨다. 둘의 간격은:

```
차이 = 블록 간 거리 + C1·(vh + Ht) − S5·(vh + Hs)     ← 뷰포트 높이에 선형 의존
```

| 뷰포트 | 실제 순서 | 겹침 |
| ---: | :--- | ---: |
| 600 | 정1 → 정2 → 정3 → 정4 → **카1** → 정5 → 카2 → 카3 | 64px |
| 900 | 정1 → 정2 → 정3 → **카1** → 정4 → 정5 → 카2 → 카3 | 208px |
| 1400 | 정1 → 정2 → **카1** → 정3 → 정4 → **카2** → 정5 → 카3 | 448px |

**화면이 클수록 깊이 겹친다.** 임계값을 맞춰도 다른 높이에서 다시 어긋나므로, 숫자가 아니라
**기준을 고쳐야** 했다. 한 요소(`.timeline`)를 기준으로 두 블록이 구간을 나눠 쓰면
순서가 산술로 보장된다 — 간격이나 높이가 바뀌어도 구간의 대소 관계는 그대로다.
검증: 600 / 760 / 900 / 1200 / 1600px 전부 `정1→정2→정3→정4→정5→카1→카2→카3`.

**[부수 교정 — 막대와 점을 한 배열로]** 막대 폭은 선형 보간, 점 점등은
`floor(fill × stopLast)`로 **각각** 계산하고 있었다. 지금은 임계가 고르게 놓여 있어
일치하지만, `STOP_AT` 한 값만 고르지 않게 바꿔도 조용히 어긋난다.
둘 다 `STOP_AT` 배열에서 직접 내도록 묶었다 — **어긋나는 쪽으로 고칠 수 있는 코드를 남기지 않는다.**


**[막대를 점 단위로 (오너 지적 2026-11-10)]**

"활성화가 점까지 단위로 됐으면 좋겠는데 모호하게 켜지는 부분이 있다."

점·제목·본문은 전부 **이산**(임계를 넘는 순간 바뀐다)인데 **막대만 연속**이었다.
스크롤이 정거장 사이에 멈추면 막대 끝이 점과 점 사이 허공에 떠서, 어디까지 켜진 것인지가
흐려졌다. 한 블록 안에서 같은 상태를 두 가지 방식으로 그리고 있었던 셈이다.

막대 폭을 `stopReached / stopEnd`로 바꿨다 — **0 / 0.25 / 0.5 / 0.75 / 1 다섯 값만** 갖는다.
사이는 CSS 전이(`--duration-fast` · `--ease-out`)가 메우므로, 막대는 **다음 점까지
건너가는 동작**이 되고 멈춘 자리는 항상 점 위다. 구 전이값 0.12초는 폭이 스크롤을 연속으로
따라가던 시절 프레임을 메우려던 값이라, 이산으로 바뀐 뒤에는 건너뛰듯 끊겨서 함께 고쳤다.

검증: p = 0 ~ 0.5 구간 전수에서 막대가 다섯 값 외의 폭을 갖는 지점이 없다.


### 20-9. 모바일 정렬 · 카드 3번 점등 시점 (오너 지적 2026-11-12)

**[① 모바일에서 정거장이 가운데로 몰렸다]**

`.journey-stop`은 index.css **버튼 공통 골격 그룹**에 편입돼 있고, 그 그룹이
`justify-content: center`를 준다. 데스크톱은 `flex-direction: column`이라 세로 분배라서
무해했는데, 모바일에서 `row`로 눕히는 순간 **칸 내용이 전부 가로 가운데로 몰린다.**
칸마다 제목 길이가 달라 점의 x좌표가 제각각이 되고, 섹션의 나머지가 전부 좌측인데
이 목록만 가운데로 떠 보였다 — §9-15가 기록한 *"서브카피만 가운데로 떠서 타이틀 좌단과
어긋난"* 사고와 **같은 유형**이다. 공통 골격에서 물려받은 값은 축을 바꾸면 뜻도 바뀐다.

조치: 모바일에서 `justify-content: flex-start`. 더불어 연도에 `min-width: 5rem`을 줘
제목 좌단을 맞췄다(최장 `2007 — 2009`가 약 74px이라 세 로케일 모두 들어가고 6px 여유).

**[② 터치 히트 영역]** 모바일 칸 높이가 약 36px으로, 지면이 이미 가진 44px 규범
(index.css `@media (pointer: coarse)`의 `.rl-af-btn`·`.daily-nav-btn` 그룹) 아래였다.
새 규칙을 쓰지 않고 **그 그룹에 셀렉터를 추가**했다.

**[③ 카드 3번이 화면을 떠나며 켜졌다]**

구간을 나누며 카드를 0.38 / 0.55 / **0.72** 로 밀었는데, 0.72는 `.timeline` 윗변이
노트북 높이에서 **음수**가 되는 지점이었다:

| 뷰포트 | 0.72일 때 타임라인 윗변 | 0.60일 때 |
| ---: | ---: | ---: |
| 600 | **−87px** (카드 윗부분 잘림) | 28px |
| 760 | **−42px** (잘림) | 92px |
| 900 | −3px | 148px |
| 1400 | 137px | 348px |

0.60은 **구 구조가 쓰던 값 그대로**다. 구간을 나누느라 밀었던 것을 되돌리고,
정거장 끝을 0.34 → 0.30으로 당겨 순서를 지켰다.

최종: 정거장 0.02 / 0.09 / 0.16 / 0.23 / **0.30** · 카드 **0.38** / 0.49 / 0.60.
600~1600px 전수에서 `정1→정2→정3→정4→정5→카1→카2→카3` 유지.


### 20-10. 모바일 전면 점검 · CTA · 주요 수치 (오너 지적 2026-11-12)

**[① 점등 기준을 정규화 진행값 → 뷰포트 비율 선으로]**

`useScrollProgress`는 `(vh − top) / (vh + 요소높이)`라 값이 **요소 자신의 높이로
정규화**된다. 같은 0.30이 요소가 커지면 전혀 다른 화면 위치를 가리킨다.
`.timeline`은 데스크톱 354px인데 모바일에서 카드가 세로로 쌓여 **1191px(3.4배)** 가 된다.

실측(390×700) — 오너는 "마지막 불 타이밍이 애매하다"고 했는데 실제로는 더 나빴다:

| | 블록 윗변 | |
| :--- | ---: | :--- |
| 정거장1 | 79px | 유일하게 화면 안 |
| 정거장2 | −54px | 잘림 |
| 정거장3 | −186px | 잘림 |
| 정거장4 | −318px | 잘림 |
| 정거장5 | **−451px** | 블록(475px)이 거의 다 지나간 뒤 |
| 카드1 | −19px | 타임라인 윗변이 이미 화면 위 |

**정거장 2~5번과 카드 전부가 화면에서 사라진 뒤에 켜지고 있었다.**

비율 선은 **vh에만 의존**한다 — 요소가 커지든 작아지든 "화면 28% 지점"은 그대로다.
정거장: 블록 윗변이 **78% → 28%** 를 지나는 동안 다섯 칸. 카드: 각 카드 윗변이
**45% / 30% / 15%**. 순서(정거장 5 → 카드 3)는 문서 순서와 두 블록 간 거리로 담보된다:

```
여유 = (정거장블록 + 간격 + 32) − (카드선 − 정거장끝선)·vh
vh 600→220px · 900→169px · 1400→84px · 1600→50px   (전 구간 양수)
```

부수로 `useScrollProgress`를 JourneySection에서 걷었다. 그 훅은 프레임마다 setState 해서
스크롤 내내 리렌더가 돌았는데, 새 핸들러는 **값이 바뀔 때만** 갱신한다.

**[② 모바일 레일 복원]** 세로 목록이라 가로 레일·막대를 껐는데, 그러면서 선을 통째로
없앴다 — 점만 다섯 개 떠 있으면 연대기로 읽히지 않는다(오너: "왜 모바일엔 라인이 없을까 ㅎ").
구 경험 5단의 `.exp-item::before`가 쓰던 방식 그대로, 자기 점에서 다음 점까지만 긋고
**지나온 구간은 색이 들어와 진행 막대 노릇을 겸한다**(`data-passed`).

**[③ 모바일 정렬]** `.journey-stop`을 버튼 공통 골격 그룹에 넣을 때 `cursor`만 보고
넣었는데 그 그룹이 `justify-content: center`도 준다. 세로일 때는 무해했으나 가로로 눕히는
순간 **칸 내용이 전부 가운데로 몰렸다.** `flex-start` + 연도 `min-width: 5rem`으로 교정.
터치 영역도 36px로 지면 규범(44px) 미달이라 기존 `@media (pointer: coarse)` 그룹에 편입.

**[④ 연재 CTA 모바일 비노출]** `position: fixed`로 **화면 하단 중앙을 68vw 차지한 채
끝까지 따라다닌다.** 데스크톱은 우하단 여백에 비켜서지만 모바일엔 비켜설 여백이 없다.
이미 `@media (max-height: 640px)`에서 같은 이유로 물러나는 선례가 있어 조건만 넓혔다.
연재로 가는 길은 GNB와 Proof of Work의 Planner's View 카드가 이미 갖고 있다.
모바일 2줄 레이아웃 규칙은 **되살리는 결정이 한 줄로 끝나도록 남겨뒀다.**

**[⑤ 주요 수치 부각]** 28~33.6px이라 캡션·라벨에 묻혔다. 33.6~38.4px(`--fs-3xl` →
`--fs-4xl`)로 올려 지면에서 **두 번째로 큰 글자**가 되게 했다.
카운트업은 이미 돌고 있었다(값에 비례한 600~1400ms + 칸별 100ms 스태거).
`tabular-nums`를 더해 세는 동안 자릿수가 바뀌어도 폭이 흔들리지 않는다 — 2026-11-04에
좌측 정렬로 **피했던** 흔들림의 직접적인 해법이다.


### 20-11. 통계 3등분 밴드 · 모바일 카드 스와이프 (2026-11-12)

**[① 주요 수치 — 원인은 정렬이 아니라 폭이었다]**

"밋밋하다"의 실제 원인을 재보니 **실폭 510px / 콘텐츠 1136px — 오른쪽 55%가 비어** 있었다.
디자인된 밴드가 아니라 왼쪽 조각으로 읽혔다. 가운데 정렬도 후보였지만 블록 크기는 그대로고
자리만 옮기므로 원인을 건드리지 못하며, 섹션에 가운데 축이 하나 더 생긴다 — 이 섹션은
그 문제로 이미 두 번 고쳤다(§9-15 · 2026-11-01 서브카피 · 2026-11-04 이 블록 자신).

**좌단 축은 두고 시작점만 고르게** 떨어뜨렸다: `grid-template-columns: repeat(3, 1fr)`,
폭은 `--measure`(바로 위 리드가 쓰는 폭이라 헤더가 한 덩어리로 읽힌다).

| | 칼럼 | 시작점 |
| :--- | ---: | :--- |
| 데스크톱 | 244px | 0 / 308 / 616 |
| 모바일(390) | 87px | 0 / 103 / 206 |

**모바일**은 구 구조가 `flex-wrap`이라 **2칸 + 1칸**으로 접혀 어느 쪽도 아닌 모양이 됐다
(오너 지적). 3등분을 유지하고 간격만 64 → 16px로 줄여 **밴드 모양을 두 폭에서 같게** 했다.
칸이 87px로 좁아 라벨이 1 / 1 / **2**줄로 갈리는데(`PAYMENT METHODS`가 접힌다) 그대로 두면
**숫자의 y가 칸마다 어긋나므로**, 라벨에 두 줄 자리를 미리 잡아 세 숫자를 한 선에 세웠다.

**[② 모바일 카드 — 세로 나열 → 가로 스와이프]**

| | 세로 나열 | 스와이프 |
| :--- | ---: | ---: |
| 세로 비용(390×700) | **1,191px** (화면 1.7개) | **430px** (0.6개) |

그 1,191px가 하는 말이 **리드 한 문장(44자)을 214자로 늘린 것**이라 비용이 더 컸다.
데스크톱이 이미 좌→우 한 줄이므로 **세로 전치 쪽이 예외**였고, 스와이프는 읽기 축을
데스크톱과 일치시킨다.

구현은 Belief 개념 카드와 **같은 패턴**이다 — 한 지면에 캐러셀을 둘로 만들지 않는다:
`overflow-x: auto` + `scroll-snap-type: x mandatory` + `scroll-snap-align: center` +
스크롤바 숨김 + `width: 80vw; max-width: 290px`. `80vw`가 핵심이다 — **다음 장이 엿보여야
스와이프가 발견된다.** 점·화살표는 넣지 않았다(Belief에 없고, 넣으면 새 장식이다).

**점등 규칙도 함께 바꿨다.** 가로 스와이프에서는 세로 선이 뜻을 잃으므로, Belief와 같이
**뷰포트 가로 중앙에 가장 가까운 한 장**만 켜고 완충 거리 50px으로 경계 떨림을 막는다.
스와이프는 컨테이너 자신의 스크롤이라 `window` 이벤트로는 안 잡혀 `.timeline`에도
리스너를 건다. 데스크톱은 가로 한 줄이라 기존 세로 선(45 / 30 / 15%)을 그대로 쓴다.

카드 높이는 본문 줄 수 때문에 348 / 374 / 374px로 갈리는데, 가로로 세우면 그 차가 바로
보이므로 `align-items: stretch`로 가장 긴 장에 맞춘다.
